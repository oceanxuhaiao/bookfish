# 受控浏览器出站方案 v0.1

日期：2026-11-21。分支：codex/txt-acquisition-hardening；承接 669aeb3。

状态：用户已授权本次安全架构设计与可行性验证；设计及传输实验完成，完整隔离方案与产品实现尚未完成。不得据此恢复生产浏览器获取或宣称 P0 已修复。

## 决策

采用“独立浏览器配置文件 + 固定 IP 的受控代理 + 独立于浏览器配置的出站限制”作为验证方向。必须先证明出站限制覆盖直连及回环，再开放浏览器获取。不能把浏览器启动参数、自检心跳、最终 URL 校验或一次代理成功当作不可绕过的安全证明。

保留浏览器自身 TLS、Cookie 和证书校验；不导出日常浏览器 Cookie，不安装本地根证书，不做 HTTPS 中间人解密。本轮不修改日常浏览器、生产 Coopanion、防火墙、系统代理、账户或虚拟网络。

独立配置文件是体验变化：它不会自动拥有日常配置文件的登录态。公开资源无需登录；以后验证登录资源时由用户选择网站并在受控浏览器内自行正常登录。不能继续承诺“装在日常浏览器即可安全获取所有资源”。

## 选项比较

| 方向 | DNS 与重定向 | 登录态与影响 | 决定 |
|---|---|---|---|
| 原扩展改 redirect:error + DNS 预检 | 可拒绝自动 HTTP 重定向，未绑定浏览器连接 IP | 不改体验，无新权限 | 必要修复，但不足以单独验收 |
| Node 固定 IP 直接取页面/文件 | 可逐跳校验和固定 IP | 无浏览器登录态；不能冒充浏览器通道 | 用于公开直连路径；复用安全原语，保留独立能力边界 |
| 日常浏览器扩展新增 proxy/debugger 权限 | 代理配置或请求拦截有帮助，不能单独证明所有出站均受限 | 权限扩大，可能影响同一配置文件其他页面 | 不选，不能为免重启而隐藏全局影响 |
| 独立浏览器 + CONNECT/HTTP 固定 IP 代理 | 代理掌握目标 DNS 和实际 TCP 连接 | TLS/Cookie 留浏览器；代理看不到 HTTPS URL 路径 | 作为传输层方向；必须叠加外部限制 |
| 只有 Windows Sandbox/虚拟机 | 隔离文件不等于隔离网络；联网时仍可能访问内网 | 新环境和登录体验 | 只能作为隔离实验容器，不单独等于安全网关 |
| 独立环境 + 默认拒绝的网络出口 + 代理 | 有条件建立完整边界 | 成本更高，需要明确系统能力与安装权限 | 完整验证方向，具体限制机制须先在隔离环境证明 |

没有宣称代理消除了所有 DNS 风险：此方案消除的是“预检后交给另一个解析器重新选择连接地址”的工程窗口；操作系统路由、VPN、管理员篡改、代理漏洞和浏览器漏洞属于另行说明的信任边界。

## 威胁与信任边界

网页、链接、重定向、DNS 响应、模型工具参数、扩展上传、迟到消息均不可信。信任 BookFish 的本地策略、代理和操作系统隔离执行机制；不抵御已能修改这些组件的本机管理员。

“不访问未授权内网”包括字面 IP、域名解析到私网、混合 DNS、元数据、IPv4 映射 IPv6、WebSocket、脚本/图片/iframe/跳转、UDP、QUIC、WebRTC、代理失效回退、旧会话与连接复用。不能只检查主文档。

本地桥是明确授权的控制通道，必须精确到固定地址、端口和实例；不允许把整段 127/8 或 localhost 任意端口作为绕过白名单。公网端口第一版仅 http:80 和 https:443；扩大端口属于后续明确配置，不由模型自行决定。

## 数据流与职责

```text
BookFish：URL 预检、来源授权、任务与租约
    ↓ 只向受控实例派发
独立 Edge/Chrome 配置文件：后台获取页面或文件
    ↓ 所有网络出口受外部限制；禁止直接回退
受控 HTTP/CONNECT 代理：认证、来源范围、DNS 校验、固定 IP
    ↓ net.connect(已校验字面 IP)，不再解析域名
公网源站
    ↓ 浏览器按大小上限流式收字节
原有桥：租约校验、分块去重、独立 .part、磁盘大小与哈希复核
    ↓ 原子提交原始文件
原有宽松导入 → SelectionCoordinator
```

代理和 BookFish 通信边界不能成为对网页开放的通用转发服务。桥保持原有 127.0.0.1 绑定；若实验采用跨虚拟机架构，必须另外设计经认证的受限中继，不能直接把桥改成 0.0.0.0。当前 v0.1 尚未选择跨 VM 中继实现，不隐含授权开放新监听接口。

### 代理连接规则

1. 认证有效且实例处于允许联网状态后，才解析请求。只接受严格格式 HTTP 绝对 URI 和 HTTPS CONNECT authority；拒绝 userinfo、片段、歧义 authority、非法端口、升级为其他协议及前置隧道数据。
2. 初始 URL 与每个候选先在 BookFish 执行统一策略；代理执行连接前第二道策略，不信任上游给出的“已检查”标记。
3. 对目标域名一次取得全部地址，任何非公网结果均拒绝。选定一个经过校验的字面 IP，并将该 IP 直接用于 socket。禁止默认 lookup、系统代理、DIRECT 回退和未检查的备用 IP。失败重试必须重新完整验证。
4. HTTP 转发验证 absolute URL 与 Host 一致，只转发必要头，移除 hop-by-hop 与 Proxy-Authorization，禁止上游代理链和 CONNECT 到非 443。
5. CONNECT 在拨号前检查 authority 和 DNS，然后向固定 IP:443 建立隧道。浏览器仍按原始域名发送 TLS SNI、校验证书和发送 Cookie；代理不解密。
6. CONNECT 不能识别隧道内路径、Cookie、跳转或下载大小。它只保证该隧道连接到已校验公网 IP；URL/来源授权、redirect:error、流式限制仍由扩展执行。不能把 CONNECT 认证 token 作为目标站请求头。
7. 不信任隧道内的 HTTP Host/SNI 与 CONNECT 一定相同；不解密时无法证明这种应用层一致性。公网 IP 安全保证仍在，但若以后需要严格限制“访问哪一个虚拟主机”，须另做来源威胁分析，不冒称代理已经提供该保证。
8. 所有隧道和 HTTP 连接有实例、任务有效期、字节/并发/空闲上限；撤权立即拒绝新连接，并关闭该实例存量连接。HTTP/2 复用不会改变已连 IP，但不能允许跨任务保留过期出站许可。

### 外部出站限制：尚未闭合的核心门槛

必须独立于浏览器配置强制：受控浏览器及网络子进程只可连接精确代理端点和必要的精确桥端点；其他 IPv4/IPv6 TCP/UDP 全部拒绝。DNS 只由代理按策略处理，浏览器不能直连 DNS/DoH。代理停止、扩展卸载、启动参数错误、任务撤销或保护组件失效均关闭获取。

候选落地方式为隔离环境中的 WFP/受限网络执行机制，或仅允许网关出口的独立虚拟网络；二者都需要专项证明。Windows 普通防火墙按浏览器安装路径配置，可能连带日常浏览器；默认规则、子进程、loopback 过滤语义不能凭推断接受。不得用“显式 Block All 后添加 Allow 代理”伪造例外规则，Windows 显式 block 优先于冲突 allow。

单纯虚拟网卡只允许网关，仍不能阻止浏览器访问其所在系统本地回环服务；必须额外验证本机回环、调试端口、桥端口和其他端口限制。该问题未解决前不建立受控实例就绪状态。

Chromium 必须去除隐式回环/链路本地绕过（手动代理的 `<-loopback>` 规则）；不使用含 DIRECT 的 PAC/回退列表。启动参数关闭 QUIC、非代理 WebRTC 等只能减少路径，不能取代外部限制。Chrome proxy API 需要新增 proxy 权限且影响配置文件级设置；方向上优先用独立进程启动配置，暂不增加该权限。

### 扩展与 CDP 一致策略

- 扩展 page/file 均使用 redirect:error；遇到重定向提示重新发现最终资源，不读 unsafe 响应内容。页面在读取过程中按字节限制 8MiB，文件 100MiB；Content-Length 只作提前拒绝，仍累计实际字节。
- CDP 仅连接由控制器创建并识别的专用浏览器实例；不接受“端口为回环就可信”。旧的任意用户调试端口路径在安全模式下 fail-closed。
- CDP 若保留页面导航，必须在导航前启用请求拦截、禁止不需要的脚本/worker/子资源，并拒绝无法确认的请求；外部出口限制仍负责最终连接边界。HTTP 重定向第一版也拒绝。
- 代理连接成功不等于准备完毕。只有限制机制安装与负向探针均通过、实例身份绑定、桥配对后才能派发任务；保护状态失效时停止派发，撤销租约和关闭隧道。不把可伪造健康回执当作 OS 隔离证明。

## 来源授权、凭据与隐私

- 固定桥主机权限保持精确；公网主机访问改为 optional_host_permissions，由扩展弹窗中的用户操作为明确来源申请。扩展不读取或导出 Cookie API，不新增 cookies 权限。
- 任务只能请求本机已经授权的 exact origin。页面中的第三方下载链接只产生候选，不自动授予第三方登录态访问；新来源需用户操作授权。模型不能批准来源，不能把“同主域”当作同源。
- CONNECT 的源站 Host 可见、HTTPS 路径不可见。代理只记录任务/实例、规范化 host、端口、拒绝码、连接计数和字节；不记录 URL 查询、原始头、Cookie、Authorization 或隧道内容。不启用 TLS keylog、浏览器 NetLog 全量内容和系统证书替换。
- 仅用获授权受控浏览器自己的登录态；HTTP 明文会使代理看见请求头，登录资源首版限 HTTPS，HTTP 公开资源不带凭据。原文与签名 URL 只在获取任务内存存活，历史仅留脱敏来源和 SHA-256；重启需重新发现。
- 使用同一凭据请求每个来源，仍受浏览器 Cookie/SameSite 等规则约束；不能承诺所有已登录网站必然可用。失败不得读取用户日常 profile 数据库补救。

## 与其他 P0 修复的接口

代理不能修复 .part 污染和重复消费。仍需 jobId+attemptId+consumerId+leaseToken，领取原子化；迟到上传拒绝；租约过期后换 attempt 与独立文件。完成前按磁盘重新计算大小/SHA，成功才 commitRaw；失败关闭句柄再清理该次 .part。已提交原件不受清理影响。下一轮实施单独保留断线30%重试、双消费者和旧租约测试。

本方案不改 Library.importFile 的语义，不改书籍数据结构、阅读/确认/记忆，不新建队列或模型客户端。网络安全、授权、流式限制、哈希、租约均确定性本地完成，无新增模型调用。新增错误只返回短失败码和可执行建议；不发送安全实验日志或代理上下文给模型。Token 实际差异尚未测量，不宣称节省。

## 实施顺序与验收门槛

1. 先选定可独立限制浏览器全部网络子进程及回环的机制，形成权限清单、安装/卸载/回滚脚本及精确变更对象；在隔离实验环境验证。不改全机防火墙默认策略，不触及日常 msedge/chrome 的网络行为。若无法达到，浏览器路径继续关闭。
2. 实现连接层与代理：拒绝类地址无上游 dial；受控 DNS 第一次公网、第二次私网时第一条连接固定原IP，第二条新连接被拒；代理断网/停止时无直连回退；HTTP Host、CONNECT、IPv6、恶意authority全覆盖。
3. 修改扩展/CDP统一门禁、来源可选权限、拒绝重定向、页面/文件流式限制；实现桥租约/.part/脱敏。受保护SSM区段如需行为改动仍须先分析审核。
4. 用真实独立 Edge 首先做 canary：初始私网、302回环、302元数据、混合DNS、重绑定、iframe/image/script/fetch/WS、WebRTC UDP、QUIC、loopback任意端口、关闭代理、卸载扩展、错误启动配置、重启/迟到租约、关联网开关。
5. canary只访问专门建立的测试服务和测试网络；每个场景先用合法测试客户端校验canary确实可达，再证明受控浏览器目标端请求/连接计数为0。只观察“工具报错”或应用日志不足以通过；预连接TCP/TLS也计入禁止目标访问。
6. 验证合法公网页面/TXT原字节与SHA、瑕疵文件入架、断线重试、双扩展实例，最后在隔离Coopanion目标宿主验证。原阶段2–6其他质量、性能、SSM、文档和发布门槛保持有效。

仅在第1步明确具体机制之后，才可能形成需要执行的系统权限变更。用户本次授权支持设计和可行性实验，不被解释为已批准未列明的系统网络策略变更或生产部署。设计交付后可先在原有授权范围内修复无关系统权限的本地P0；不得以此称浏览器门槛已闭合。
