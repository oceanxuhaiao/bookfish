## A'. 真实宿主验收结论（已执行）

17 步已在隔离宿主跑完，14/15 因 Administrator 令牌绕过 ACL 未能触发、以 `tests/import-batch-rename-retry.test.ts` 6/6 替代。完整矩阵、SHA-256、截图索引与 5 项真机新发现见 [`HOST-ACCEPTANCE.md`](./HOST-ACCEPTANCE.md)。其中两项**改变设计结论**，必读：

- **§3-A Worker `maxEntries=400` 使真 ZIP64 无法进入第二道内容检查** —— 100 本限制仍有效，但生效机制是 Worker 条目上限；`books` 只能是 `null`。§C 步骤 4/5 的文案已据此修正。
- **§3-B 拒绝/失败态仍显示「开始导入」按钮**，点击抛 `Import batch is empty`（待修）。

## B. 已知限制（设计取舍）

| # | 限制 | 说明 |
| --- | --- | --- |
| B1 | 索引不可读时必然解压一次 | 这是"必须有第二道真实内容检查"的直接代价：读数一次完整解压 + 一次 SHA-256（每本流式计算）。换来的是 100 本限制在 ZIP64 上也不再失效 |
| B2 | 索引不可读时峰值磁盘需求更高 | 归档与解压树同时存在，峰值 = `zipBytes + 实际解压量`，受 `workspaceBytes`（1.5 GiB）约束 |
| B3 | 每次解压都重算 SHA-256（含每本） | 512 MiB 归档约数百毫秒到数秒；换来"磁盘被替换一定被发现" |
| B4 | 超限归档不自动分批 | 自动分批需解压 N 次、并替用户决定分批边界；由用户决定怎么拆（`02` §4 的理由延续到 v1.5） |
| B5 | `over_limit` 不在 `resume()` 重试 | 确定性结论，重启不改变；避免反复解压必然被拒的包 |
| B6 | 拒绝名单上限 100（`rejection.names` 与 `rejected.*.names` 同策略） | 计数始终精确；名单只影响可见条目数 |
| B7 | `books: null` 时界面只能显示"未知" | Worker 中止确实无法枚举；不推算、不填 0 |
| B8 | `rejection` 校验失败即整批拒绝加载 | 宁可让用户看到"批次记录损坏"，也不静默丢弃伪造字段 |
| B9 | `check:ssm` 保持 2 REVIEW | 未 `--accept-review`，等审核方确认 |

## C. 集中式真实宿主验收步骤（v1.5 新增 / 变更项加粗）

**原则**：独立隔离宿主 + 独立 `data` 目录，绝不指向正式数据；先备份；侧载与回滚参照 v1.1 `06`。一次性观察，以宿主状态、面板文本、库快照为证据。

| 步 | 操作 | 观察点 | 判定 |
| --- | --- | --- | --- |
| 0 | 侧载 v1.5 构建，重启 | manifest 下发的 client.js 哈希 | 是本轮产物 |
| 1 | 准备素材：3 本 txt、三层嵌套文件夹、1 个正常 ZIP、**1 个 99 本 ZIP64、1 个 101 本 ZIP64、1 个 120 本 ZIP64、1 个中央目录 > 8 MiB 的 128 本 ZIP**、1 个 120 本普通 ZIP、1 个超 100 MiB 单本的 ZIP | 素材 SHA-256 先记录 | 可复现 |
| 2 | 正常 ZIP 导入 | 四态流转、解压、条目就位、ZIP 删除 | `extracted` |
| 3 | **99 本 ZIP64 导入** | 面板显示 99 本成功；报告块显示 `进批 99`、无拒绝分类 | 索引不可读也能正常导入 |
| 4 | **101 本 ZIP64 导入** | 面板显示"整包未导入：压缩包文件数量超过限制"、`压缩包声明 未知 本 / 未知 字节`、`没有发生部分导入（进批 0 本）`、`原始压缩包已保留`、`下一步：拆包`；条目列表为 0；ZIP 仍在；`.extract` 目录不存在 | 不静默导入前 100 本。**注意**：真 ZIP64 条目 ≥ 65535，在读中央目录前即被 Worker `maxEntries=400` 拦截，**不会**走到"解压后实测 N 本"，故 `books` 只能是 `null`（详见 `HOST-ACCEPTANCE.md` §3-A） |
| 5 | **120 本 ZIP64 导入** | 同上，`压缩包声明 未知 本 / 未知 字节` | 不静默导入前 100 本 |
| 6 | **中央目录 > 8 MiB 的 N 本 ZIP（条目 ≤ 400）** | `整包未导入：解压后实际得到 N 本可导入的书…`；`解压后实测 N 本 / X 字节`；`超出单批 100 本上限 M 个（books/B100.txt…）`；导入耗时明显长于普通包（必然解压） | 兜底路径生效。这才是第二道真实内容检查可达的分支 |
| 7 | **单本超 100 MiB 的 ZIP** | `整包未导入`；名单含那个大文件；`下一步：把超过 100 MiB 的单本移出` | 不导入其余本 |
| 8 | **关面板再打开（第 4 步之后）** | 同一批次仍显示完整整包拒绝区块（原因 / 本数 / 字节 / 已保留 / 下一步） | 报告持久化 |
| 9 | **重启宿主（第 4 步之后）** | 同上；且该批次不在启动时被自动重试（不出现新的解压进度） | `over_limit` 不重试 |
| 10 | **首次 ZIP 上传即失败**（选一个被截断的 ZIP） | 面板立即显示错误 + 批次卡片 + "重试解压"；历史列表出现该批次；无需重开面板 | P2-6 恢复 |
| 11 | **选文件夹：2 本 txt + 3 张 jpg** | 报告块（preview 阶段就有）显示"格式不支持 3 个（封面.jpg…）"；`共 2 本`；未开始导入 | P2-4 / P2-5 |
| 12 | **选文件夹：全是 jpg** | 报告"格式不支持 N 个"；历史列表出现 1 条 `总数 0` 的批次；不报错崩溃 | 全不支持也有记录 |
| 13 | **篡改归档**：把 ready 批次 `source.zip` 换成同长度不同内容后重试 | "内容与已验证的摘要不一致"；无新条目；ZIP 仍在 | 不导入、不丢证据 |
| 14 | **临时故障恢复**：批次目录设只读触发 rename 失败 | "文件系统或权限问题…已保留压缩包供重试"；状态仍"已校验" | 不要求重新上传 |
| 15 | 恢复权限后重试 | 成功；已入库书不重复 | 无重复条目 |
| 16 | **旧计划统计**：v1.2 时代库 | "至少累计读完 N 本" + 下界说明 | 不冒充总数 |
| 17 | 收尾：隔离 `data` 快照、截图、日志归档 | 正式数据零改动 | — |
