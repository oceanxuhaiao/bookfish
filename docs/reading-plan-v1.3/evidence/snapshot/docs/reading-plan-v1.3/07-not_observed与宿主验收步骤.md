# 07 · not_observed 清单与真实宿主验收步骤

本文件的作用：**不要把"没看到"当成"已验证"**。自动化在 jsdom + Node 环境完成，没有在隔离桌面宿主里用鼠标点过，也没有真的写 512 MiB 文件、真的把磁盘写满、真的在异种挂载上失败。以下项目全部标记 `not_observed`。

---

## A. `not_observed`（本阶段确实没有观察到，不得视为验收）

| # | 项 | 为什么没观察到 | 现有替代证据 |
| --- | --- | --- | --- |
| A1 | 真实 Cortico 桌面宿主里的批量导入页 / 计划页 | jsdom 挂载真实 World + 真实 worker，没在已安装客户端点过 | `tests/webui/batch-import.test.ts`、`tests/webui/plan-panel.test.ts`，均走 `world.webUi('zh').invoke` |
| A2 | 真实系统文件选择器（多选 / 文件夹 / ZIP / 重选） | jsdom 无法打开原生对话框，测试用构造的 `File` 注入 | 同上；原生行为取决于宿主 webview |
| A3 | 真实 512 MiB ZIP 的小分片重放内存曲线 | 不真写大文件，用 64 MiB 稀疏文件 + 256 KiB 窗口 + 源码护栏证明"只读请求区间" | `tests/import-batch-bounded-read.test.ts` |
| A4 | **>64 MiB ZIP 的前端摘要**（走 `fileSha256Hex` 而不是 `subtle`） | 端到端用例的 `File` 都很小；分片实现本身有完整单测 | `tests/webui-sha256.test.ts`（标准向量、0..4096 长度、任意分片、`File` 切片、读取失败） |
| A5 | 真正磁盘写满（ENOSPC） | 用注入的 `diskFree` 与 `workspaceBytes` 模拟拒绝，没有填满卷 | `tests/import-batch-rename-retry.test.ts` 的磁盘预检三态 |
| A6 | 真正的 rename 失败（异种挂载 / 权限拒绝） | 测试跑在同盘 NTFS，用 `vi.mock('node:fs')` 对 `.src` 目标抛 `EFAULT` 模拟 | 同上的全失败 / 部分失败两组用例 |
| A7 | 硬杀进程（SIGKILL）后的恢复 | 用"改状态 + 关库重开"等价模拟，没真的 kill 正在解压的进程 | `import-batch-rename-retry` / `import-batch-zip-concurrency` 的重启用例 |
| A8 | 真实多批次同时中断后的恢复（3 个以上 ready 批次） | 自动化只到 3 个批次，且用 spy 统计调用 | `concurrency` 的 resume 串行用例（峰值并发 = 1） |
| A9 | 真实用户库从 v1.1/v1.2 升级后的历史统计显示 | 全部测试库是合成数据 | `tests/plan-stats-complete.test.ts`、`tests/plan-display.test.ts`、`tests/webui/plan-panel.test.ts` |
| A10 | 空 ZIP 在真实界面上的可见文案 | 只断言 DOM 文本 | `tests/webui/batch-import.test.ts` |
| A11 | macOS / Linux 的路径与大小写行为 | 环境是 Windows | 路径校验是纯字符串规则，有单测 |
| A12 | 英文界面观感 | 文案已写（`say(zh, en)`），测试只断言中文 | — |
| A13 | 加密 / 损坏 / ZIP 炸弹在批量入口的端到端拒绝 | 复用 `zip-worker` 既有拒绝逻辑，未在批量入口做恶意包端到端 | 既有 `novel-runtime*` 用例覆盖拒绝分支 |

## B. 已知限制（设计取舍，不是缺陷）

| # | 限制 | 说明 |
| --- | --- | --- |
| B1 | `renameSync` 失败没有回退路径 | 任务书推荐方案：宁可让用户看到"文件系统或权限问题"，也不在预算之外复制一份。代价：异种挂载场景下该批次只能重试或换目录 |
| B2 | 前端摘要对超大文件耗时线性增长 | 1 MiB 切片、纯 JS 实现（不依赖 Worker），512 MiB 约需数秒；期间界面显示"正在上传"前的准备态。选择纯 JS 是为了避免 `crypto.subtle` 在 jsdom / 老 webview 下不可用 |
| B3 | `statsComplete` 是"保守下界"标记 | 迁移来的空队列也标 `false`（"至少读过 0 本"永远成立），不追求精确最小化 |
| B4 | `zipReselect` 对无锚点批次只给"新建批次"路径 | 这是任务书要求的保守策略，不提供"仅按大小接受"的降级 |
| B5 | 历史明细仍只保留 300 条 | 本轮只加标记与文案，不扩容、不加独立历史存储（任务书明确不要求） |
| B6 | `check:ssm` 保持 2 REVIEW | 未 `--accept-review`，等审核方确认 |
| B7 | 预算口径未变 | 100 MiB / 100 项 / 1 GiB / 512 MiB / 并发 2 全部保持；`workspaceBytes = 1536 MiB` 是 v1.2 已有的显式封顶，本轮只是让它按**真实递归占用**生效 |

## C. 集中式真实宿主验收步骤

**前置原则**：独立隔离宿主 + 独立 `data` 目录；**绝不指向正式用户数据**；先备份隔离目录；侧载与回滚参照 v1.1 `06-数据安全与回滚报告.md`。一次性准备、一次性观察，以宿主状态、面板显示与库快照为证据。

| 步 | 操作 | 观察点 | 判定标准 |
| --- | --- | --- | --- |
| 0 | 侧载 v1.3 验收构建到隔离宿主，重启 | `GET /api/webui/manifest` 下发的 client.js 哈希 | 是本轮产物 |
| 1 | 准备素材：3 本 txt、`系列/第一部/正文/`（2 本，**三层嵌套**）、1 个 ZIP（含 2 本）、1 个空 ZIP、1 个只有 `__MACOSX` 的 ZIP、1 个与某 txt 同大小不同内容的文件 | 素材字节数与 SHA-256 先记录 | 可复现 |
| 2 | **嵌套目录的占用统计**：导入 `系列/第一部/正文/` 文件夹 | 面板占用/峰值数字 ≥ 实际字节数；不触发超预算拒绝 | 数字与资源管理器一致 |
| 3 | **真实 ZIP**：上传含 2 本的 ZIP | 四态流转、`peakBytes` 非 0、解压后 ZIP 删除、条目就位 | `extracted`，无残留 `.extract` 目录 |
| 4 | **空 ZIP / 只有隐藏文件** | 面板显示"解压完成，但未发现可导入的书籍…不会自动加入阅读计划"；重启宿主后**不再**解压 | `extracted` + `completed`，`report.archives = 0` |
| 5 | **ZIP 中断恢复**：上传到一半关宿主，重启 | 出现"重新选择 ZIP"；选**同大小不同内容**的包 → 被拒且提示指纹不一致；再选原包 → 完成 | 错误包进不去，原包可恢复 |
| 6 | **无可信指纹的旧批次**：构造一个 v1.2 遗留的中断批次（无 `sha256` / `claimedSha256`） | 不显示"重新选择"按钮，显示"请新建一个批次重新导入" | 不静默接受同大小文件 |
| 7 | **并发**：网络面板里对同一批次同时触发两次 `import_batch_zip_finish` | 只有一次解压；`items` 不重复；`.src` 各 1 份 | 与自动化一致 |
| 8 | **部分失败重试**：解压过程中把批次目录设为只读制造 rename 失败 | 错误提示含"文件系统或权限问题…已保留压缩包供重试"；ZIP 仍在；已成功书籍与进度仍在 | 重试后不重复导入 |
| 9 | **旧计划历史**：用一个 v1.1 时代的库（归档被裁过）打开计划页 | 显示"至少累计读完 N 本" + 下界说明 | 不冒充完整总数 |
| 10 | **新计划历史**：新读完 3 本 | 显示"累计读完 3 本"，无下界说明 | 文案随标记切换 |
| 11 | 收尾：记录隔离 `data` 快照、截图、宿主日志；需要时回滚 | 证据归档 | 正式数据零改动 |

**如果宿主不可用**：2–10 全部保持 `not_observed`，本阶段只交付自动化证据，不声称真机验收通过。
