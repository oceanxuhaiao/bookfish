## 八个必须看的结论

1. **目录占用是真递归。** `dirTreeBytes()` 走完整目录树（嵌套目录计入、`lstat` 跳符号链接、遍历中途消失容忍、**目录读异常向上抛而不是静默记 0**）。测试侧用**独立的递归实现**交叉验证，三层嵌套 ZIP（`系列/第一部/正文/甲.txt`）统计与预算判定一致（`01`）。
2. **部分解压失败后预算重新算。** 可用额度 = `min(batchBytes − 已有暂存, workspaceBytes − ZIP − 已有暂存)`；已有暂存由真实目录递归实测，不靠记录推算；**磁盘剩余不足在写入前拒绝**（`statfs`），不写满再报错；已成功搬移的书、已有阅读进度不丢，重试不重复导入、不破坏预算（`01`）。
3. **不受预算约束的复制回退已删除。** `copyThenUnlink` 整段移除：`renameSync` 失败即抛错并写明原因，**保留 ZIP 与已搬移的 `.src`**、清理解压目录、批次置可恢复状态。没有"绕过预算的第二条路"（`01`）。
4. **分片重放不再整读文件。** `zipChunk` 与 `stage()` 的重复分片比较改 `readRange()`（`openSync` + 固定 256 KiB buffer + `readSync`），只读请求区间；源级护栏测试断言源码中不存在 `readFileSync` / `copyThenUnlink`，512 MiB 归档小分片重放不读整文件（`02`）。
5. **解压并发被真正收口。** 同批次 single-flight（`Map<batchId, Promise>`，在首个 `await` 之前**同步注册**，见 `src/import-batches.ts:401-410`）；`extracted` 返回 `alreadyExtracted`、非 `ready` 明确拒绝；`resume()` 改串行链，恢复解压峰值并发恒为 1；`Promise.all` 两次 `zipFinish` 拿到**同一个结果对象引用**（`03`）。
6. **ZIP 重选必须证明"是同一个压缩包"。** 首传即建立稳定摘要（前端 1 MiB 分片增量 SHA-256，不整读；服务端完整校验后才写 `sha256`），客户端声明存 `claimedSha256` 且**粘性持久**（不接受换值、拒绝时**不清除**）；两者都缺失时**明确拒绝重选**并提示新建批次；错 claim 不可能通过"删掉 claim"放行任意同长文件（`02`）。
7. **无内容归档有明确终态。** 空 ZIP / 纯隐藏 / 纯不支持 / 纯目录：解压完成 → `extracted` + 批次 `completed` + 删除 ZIP，重启 `report.archives === 0`（不重复解压），界面明示"已完成解压、未发现可导入书籍、可删记录"，**不自动入计划**（`03`）。
8. **历史统计区分"累计"与"至少累计"。** 新增 `statsComplete` 标记：新计划 `true`；缺 `stats` 的旧计划回填 `false`（可确认下界）；有 `stats` 无标记的 v1.2 计划视为 `true`（计数从诞生起就在）；`migrateLegacyQueue` 标 `false`。界面按标记输出"累计读完 N 本"或"至少累计读完 N 本"并加下界说明（`04`）。
