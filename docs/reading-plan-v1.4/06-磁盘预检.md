# 06 · 磁盘空间预检（P2-7）

对应任务书第 7 节。

---

## 1. 问题

v1.3 的预检是：

```ts
if (free !== null && free < ceiling) throw ...
```

`ceiling` 是**批次允许的最大解压量**（默认 1 GiB）。于是一个 2 MB 的小 ZIP 也要求磁盘剩余 1 GiB；`diskFree === null`（无法测量）时直接放行——"测得准的安全"变成"测不到就假设安全"。

## 2. 现在的方案：先读归档自己的声明

`readZipPlan()` 从中央目录读出 `totalUncompressed`（详见 `04` 第 3 节）。预检顺序：

```ts
const plan = readZipPlan(zipPath);
const estimate = plan ? plan.totalUncompressed : ceiling;      // 读不出来 → 最坏情况
...
if (estimate > ceiling) throw this.fail(batchId, 'over_limit', ...);   // 预算内先拒
const free = this.diskFree(this.batchDir(batchId));
if (free === null) throw this.fail(batchId, 'disk', '无法测量磁盘剩余空间…');
if (free < estimate) throw this.fail(batchId, 'disk', `磁盘剩余 ${free} 字节，本次解压约需 ${estimate} 字节…`);
```

| 要求（任务书） | 实现 |
| --- | --- |
| 安全读取中央目录 | 只读 EOCD 尾部 66 KiB + 中央目录（≤ 8 MiB），`readRange` 定点读，不整读归档 |
| 获取声明的未压缩大小 | `uncompressed size` 求和 |
| 预计解压总量 | `totalUncompressed`（不含隐藏/目录以外的一切，无需过滤：解压产物就是这些文件） |
| 已有暂存 + ZIP + 预计总量一起算 | `ceiling` 用 `dirTreeBytes(batchDir) − zipSize` 扣掉已有暂存；`estimate` 与 `ceiling` 比较；磁盘侧再与 `estimate` 比较 |
| 保留 worker 硬限制 | `maxEntries = 400`、`maxTotalBytes = ceiling`、`maxEntryBytes = fileBytes` 原样传入 |
| 无法可靠判断时保守 | `plan === null` → `estimate = ceiling`（1 GiB 最坏值） |
| 剩余空间无法测量时不得宣称安全 | `free === null` → 拒绝并保留 ZIP（`failure = 'disk'`） |
| 不放宽 1 GiB / 1.5 GiB 预算 | 常量未改：`BATCH_STAGING_BYTES = 1 GiB`、`ZIP_MAX_BYTES = 512 MiB`、`workspaceBytes = 1.5 GiB` |

## 3. 效果对比

| 场景 | v1.3 | v1.4 |
| --- | --- | --- |
| 2 MB ZIP（解压后 5 MB），磁盘剩 100 MB | **拒绝**（100 MB < 1 GiB） | 允许（100 MB ≥ 5 MB） |
| 400 MB ZIP（解压后 900 MB），磁盘剩 200 MB | 拒绝（200 < 1024） | 拒绝（200 < 900），理由精确 |
| 磁盘剩余无法测量 | 放行 | 拒绝，提示稍后重试 |
| 解压后 1.2 GB（预算 1 GiB） | 解压中途被 worker 拒绝 | **写前拒绝**，ZIP 保留 |

## 4. 已知取舍（需要审核方知悉）

1. **中央目录预读不等于实际解压量。** 归档可以在中央目录里声明 1 MB，实际数据流更大——但这一点由 worker 的 `maxTotalBytes` / 实际写入量兜底，预检只是把"明显放不下"提前拒掉，不是唯一防线。
2. **`plan === null` 时回到 1 GiB 最坏值。** 这是保守方向：这类归档（ZIP64、分卷、超大索引）极少，而误判放行的代价是写满磁盘。产品限制在此明确：**这类归档仍要求约 1 GiB 可用空间**。
3. **磁盘剩余在解压过程中可能变化。** 预检之后仍可能 ENOSPC，此时 `classifyExtractionError()` 归为 `disk`，ZIP 保留、可重试（`01`）。

## 5. 验收（`tests/import-batch-rename-retry.test.ts` + `tests/import-batch-limits.test.ts`）

| 用例 | 断言 |
| --- | --- |
| 小 ZIP + 低于预算的剩余空间 | 允许（`estimate` 通过，`ceiling` 不通过也可） |
| 剩余空间不足以容纳 `estimate` | 拒绝，`failure = 'disk'`，无 `.extract`，ZIP 保留 |
| 磁盘剩余无法测量（`null`） | 拒绝，`failure = 'disk'`，ZIP 保留（v1.3 此处是放行） |
| 预算内但解压量超 `ceiling` | `over_limit`，ZIP 保留，报告完整 |
| 中央目录可解析 | `readZipPlan` 的条目数/总量/最大条目与 fixture 的字节数一致 |
