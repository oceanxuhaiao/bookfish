## 1. 逐条对照

| # | 验收条件 | 结论 | 证据 |
| --- | --- | --- | --- |
| 1 | ZIP 恢复失败不会破坏原始归档 | ✅ | 所有失败路径只写 `failure`/`error`，不删 ZIP（`fail()`，`src/import-batches.ts:704`）；rename 失败、磁盘不足、worker 故障用例均断言 ZIP 字节不变 |
| 2 | 每次解压都会验证 ZIP 内容身份 | ✅ | `extractArchive` 的"存在 → 长度 → SHA-256"三道检查在任何写入之前；替换/截断/无摘要三类用例 |
| 3 | `zipBegin` 不会覆盖已验证文件 | ✅ | `ready`/`extracted` 明确拒绝、`uploading` 幂等返回 offset、截断只存在于 `startUpload`；断言文件 SHA-256 不变 |
| 4 | 用户取消重新选择不会卡死 | ✅ | 准备阶段零副作用（不改状态、不删文件、不建空文件），token 内存态；两次 prepare 均成功 |
| 5 | 超限书籍不会静默遗漏 | ✅ | 120 本整包拒绝 + 报告名单；101 文件 `overflow = 1`；`batch.rejected` 持久化 + `status().report` + 界面结果块 |
| 6 | 历史统计口径正确 | ✅ | `statsComplete = marker === true`；v1.2 回填计划判为下界；界面对应"至少累计读完" |
| 7 | 磁盘预算既安全又不会不合理拒绝小文件 | ✅ | 按中央目录 `totalUncompressed` 预检；`null` 拒绝；1 GiB / 1.5 GiB 未变 |
| 8 | 原有阅读计划和批量导入功能无回归 | ✅ | 全量 128 files / 1349 passed；v1.3 的 1325 个用例全部保留通过 |
| 9 | 完整测试通过 | ✅ | `test_exit=0`；双端 tsc、worker/webui 构建、`check:help` 全部 exit 0 |
| 10 | 审核包独立可复核 | ✅ | `SHA256SUMS` 覆盖全部交付文件；`changes.patch` 在基线 `7f5b4da` 上 `apply --check` 通过；`snapshot/` 由补丁应用树逐字节生成 |

## 2. 独立复核步骤

```bash
cd <解压后的审核包根目录>            # 含 docs/ 的那一层
sha256sum -c docs/reading-plan-v1.4/evidence/SHA256SUMS

cd E:/项目/桌面宠物/扩展/cortina/state/packages/bookfish-reading-plan
git apply --check <包内>/evidence/changes.patch
```

`evidence/snapshot/` 是按仓库相对路径展开的完整文件，可与"补丁应用后的工作树"逐字节比对（行尾差异见 `evidence/patch-apply-check.log`）。

## 4. 需要审核方裁定的三处

1. **`diskFree === null` 由"放行"改为"拒绝"**：任务书第 7 节明确"不得默认宣称安全"，因此无法测量时拒绝并保留 ZIP。代价：没有 `statfs` 的环境无法解压 ZIP（Windows/macOS/Linux 的现代 Node 均支持）。
2. **v1.2 计划一律显示下界**：包括那些"真的从零累计"的计划。若审核认为可以用别的持久化证据区分，需要先给出可验证的判据——本轮没有找到。
3. **超限 ZIP 选择整包拒绝而非自动分批**：`04` 第 3 节列了四条理由。若产品希望"自动分批续导"，需要先定义分批边界规则与磁盘成本上限。
