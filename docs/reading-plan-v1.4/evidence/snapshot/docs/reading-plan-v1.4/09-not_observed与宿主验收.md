# 09 · not_observed 清单与真实宿主验收步骤

自动化跑在 Node + jsdom 里，没有在隔离桌面宿主点过，也没有真的写 512 MiB 归档、真的把磁盘写满、真的在异种挂载上失败。以下全部标记 `not_observed`。

## B. 已知限制（设计取舍）

| # | 限制 | 说明 |
| --- | --- | --- |
| B1 | ZIP64 / 分卷 / 超大中央目录的预检退回 1 GiB 最坏值 | 这类归档仍要求约 1 GiB 可用空间；由 worker 限额兜底 |
| B2 | 每次解压都重算 SHA-256 | 512 MiB 归档约数百毫秒到数秒；换来"磁盘被替换一定被发现" |
| B3 | 重选 token 不持久化 | 重启后需再点一次按钮；换取了"替换许可不变成长期凭据" |
| B4 | 超限归档不自动分批 | 见 `04` 第 3 节的四条理由；由用户决定怎么拆 |
| B5 | `statsComplete` 对 v1.2 计划一律为下界 | 宁可对真正完整的 v1.2 计划说"至少"，也不对回填计划说"共" |
| B6 | 拒绝名单上限 100/类 | 计数始终精确；名单只影响可见条目数 |
| B7 | `check:ssm` 保持 2 REVIEW | 未 `--accept-review`，等审核方确认 |

## C. 集中式真实宿主验收步骤

**原则**：独立隔离宿主 + 独立 `data` 目录，绝不指向正式数据；先备份；侧载与回滚参照 v1.1 `06`。一次性观察，以宿主状态、面板文本、库快照为证据。

| 步 | 操作 | 观察点 | 判定 |
| --- | --- | --- | --- |
| 0 | 侧载 v1.4 构建，重启 | manifest 下发的 client.js 哈希 | 是本轮产物 |
| 1 | 准备：3 本 txt、三层嵌套文件夹、1 个正常 ZIP、1 个 120 本 ZIP、1 个同长度改字节的 ZIP | 素材哈希先记录 | 可复现 |
| 2 | 正常 ZIP 导入 | 四态流转、解压、条目就位、ZIP 删除 | `extracted` |
| 3 | **篡改归档**：把 ready 批次的 `source.zip` 换成同长度不同内容，点重试解压 | 提示"内容与已验证的摘要不一致"；无新条目；ZIP 仍在 | 不导入、不丢证据 |
| 4 | **临时故障恢复**：把批次目录设为只读触发 rename 失败 | 提示"文件系统或权限问题…已保留压缩包供重试"；状态仍是"已校验" | 不要求重新上传 |
| 5 | 恢复权限后点"重试解压" | 成功；已入库书不重复 | 无重复条目 |
| 6 | **取消重选**：点"重新选择 ZIP"后在对话框点取消 | 按钮仍在、批次状态不变 | 不卡死 |
| 7 | **选错归档**：选同长度不同内容 | 前端直接拒绝；再选原文件可继续 | 错误包进不去 |
| 8 | **120 本 ZIP** | 明确提示超限 + 建议拆分；ZIP 保留；0 条目 | 不静默导入 100 本 |
| 9 | **101 个文件的文件夹** | 报告"只接收前 100 本，还有 1 本超出上限"；再选一次可继续 | 遗漏可见 |
| 10 | **旧计划统计**：用 v1.2 时代的库打开阅读计划 | 显示"至少累计读完 N 本" + 下界说明 | 不冒充总数 |
| 11 | 收尾：隔离 `data` 快照、截图、日志归档 | 正式数据零改动 | — |
