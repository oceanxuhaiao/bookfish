# 05 · 历史统计兼容（P2-6）

对应任务书第 6 节：v1.2 保存过的旧计划可能带着**回填**的 `stats`，不能因此认定历史完整。

---

## 1. 问题

v1.2 的 `validateStats()` 在缺少 `stats` 时，用当时仍在 `archive` 里的行回填累计值：

```ts
if (raw === undefined) return { ...counted, truncated: 0 };   // counted 来自 archive 窗口
```

于是"有 `stats`"这件事有两种截然不同的来源：

| 来源 | `stats` 的含义 |
| --- | --- |
| v1.2+ 从零开始累计 | 完整历史 |
| v1.2 打开旧库时回填 | 只覆盖保留窗口内的行，**更早的已被裁掉** |

v1.3 的推导规则是"无标记 + 有 stats → 完整"（`statsProvided`），把回填值当成了总数。任务书要求：不能靠"stats 是否存在"推断完整性。

## 2. 现在的规则

```ts
// src/reading-plan.ts:216-223
const marker = (value as { statsComplete?: unknown }).statsComplete;
const statsComplete = marker === true;
```

| 磁盘形态 | `statsComplete` |
| --- | --- |
| 显式 `true`（v1.3+ 新建计划写的就是它） | 完整 |
| 显式 `false` | 下界 |
| 无标记 + 有 `stats`（v1.2 计划） | **下界**（本轮改变的正是这一行） |
| 无标记 + 无 `stats`（v1.1 及更早） | 下界 |

代价是"真正从零累计的 v1.2 计划"也会显示"至少累计读完 N 本"——文本更保守，但不会撒谎。任务书明确：宁可显示下界，也不能冒充完整历史。

## 3. 为什么不用其它证据推断

任务书允许"提交证明"来区分，前提是有**可靠**的持久化证据。当前没有：

- `createdAt` / `updatedAt`：无法区分"新库新建"与"旧库首次保存"；
- `stats` 是否存在：正是本轮要否定的依据（v1.2 会回填）；
- `archive.lengh === stats.completed`：只有从未截断过才成立，截断后无痕迹（`truncated` 字段是 v1.2 才有的，旧数据没有）；
- `schema` 版本：v1.2 与 v1.3 都是 1，且回填发生在 v1.2 读取路径里，不写版本。

因此不引入任何"未经证明的推断"。

## 4. 视图与文案

`Library.planView()` 输出 `statsComplete: plan.statsComplete === true`（布尔收敛）；`src/webui/plan.ts`：

```ts
const complete = plan.statsComplete !== false;
summary.textContent = 计划 N 本 · (complete ? '累计读完 X 本' : '至少累计读完 X 本');
historyNote = ... + (complete ? '' : '此计划由旧版本迁移而来，更早的完读历史可能已超出保留窗口，以上累计数字是可确认的下界，不是完整总数。');
```

## 5. 数据兼容

| 问题 | 结论 |
| --- | --- |
| 旧计划会丢数据吗？ | 不会。`stats` 原样保留，`validateStats` 的截断审计（`truncated` / `lastArchivedAt`）不变 |
| 新计划会不会被误判？ | 不会。`emptyPlan()` 显式写 `statsComplete: true`，落盘往返保持 `true` |
| 需要迁移吗？ | 不需要。没有重写任何已有计划；标记在下次正常保存时自然写入 |
| 能否回退？ | 能。字段可选，旧版本忽略它，读到的仍是合法计划 |

## 6. 验收（`tests/plan-stats-complete.test.ts` 7 例）

| 用例 | 断言 |
| --- | --- |
| v1.1 旧计划（无 stats） | 回填后 `statsComplete = false`，`stats.completed` 等于归档内行数 |
| **v1.1 旧库被 v1.2 打开并保存**（有回填 stats，无标记） | `stats.completed = 37`（大于归档窗口）保留，`truncated = 31` 保留，`statsComplete = false` |
| v1.2 全新计划（有 stats，无标记） | `statsComplete = false`（无法证明，宁可保守） |
| 显式 `true`（v1.3+） | 保持 `true` |
| 显式 `false` | 保持 `false` |
| `migrateLegacyQueue` | `false` |
| 归档截断 | 不改变 `statsComplete` |

界面文案：`tests/webui/plan-panel.test.ts` 断言两个分支（"累计读完"与"至少累计读完"）及下界说明；`tests/plan-display.test.ts` 断言视图字段。
