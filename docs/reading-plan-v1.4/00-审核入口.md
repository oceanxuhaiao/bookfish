## 七个必须看的结论

1. **临时失败不再等于归档丢失（P1-1）。** `resume()` 原本把所有解压异常压成 `needs_reselect`；现在只有"归档缺失 / 无法证明身份"才要求重选，磁盘不足、rename 拒绝、权限、worker 故障一律**保留 `ready`** 并记录 `zip.failure`，ZIP 级重试始终可用（`src/import-batches.ts:704` 的 `fail()`）。顺带解除了"批次已有条目就不能重选"的死结（`:928`）。
2. **每次解压前重新验证内容身份（P1-2）。** `extractArchive()` 在创建解压目录之前依次校验：文件存在 → 长度等于声明 → **服务端 SHA-256** 等于已接受的摘要（无服务端摘要时退回首选的 `claimedSha256`，两者皆无则拒绝）。不一致时不把任何字节交给 worker，保留现场（`01`）。
3. **`zipBegin` 不再截断已验证的字节（P1-3）。** 首次创建；`uploading` 幂等并返回**真实 offset**、绝不截断；`ready` 与 `extracted` 明确拒绝；只有 `needs_reselect` / 失效 `ready` 凭**一次性 token** 才允许替换。截断现在只发生在一处（`startUpload`，`:809`）（`02`）。
4. **重选是两阶段事务（P1-4）。** 准备阶段只校验并返回 token + 期望摘要，**不改状态、不删文件、不建空文件**；用户取消文件对话框后批次原样可用。确认阶段由 `begin` 携带 token 完成，摘要不符被拒且可再次重选（`03`）。
5. **超限不再静默遗漏（P1-5）。** 新增 `batch.rejected`（分类计数精确、名单上限 100）+ `status().report`；ZIP 先读中央目录得到条目数与解压后总量，超出 100 本或批次预算时**整包拒绝、保留 ZIP、提示拆分**，不会"导入前 100 本然后删包"。多文件/文件夹导入同样报告遗漏、过限、超预算、重复与不支持数量，并提示继续导入剩余（`04`）。
6. **历史统计只认显式 true（P2-6）。** `statsComplete` 改为 `marker === true`：v1.2 计划（有回填 `stats`、无标记）现在判定为**可确认下界**，界面显示"至少累计读完 N 本"（`05`）。
7. **磁盘预检按归档自己的声明（P2-7）。** 从中央目录读未压缩总量，按"实际预计"而不是 1 GiB 最坏值比较：小 ZIP 不再被要求 1 GiB 剩余空间；磁盘剩余**无法测量时拒绝**而不是默认安全；1 GiB / 1.5 GiB 预算一字未改（`06`）。

## 本轮修复的真实缺陷（如实记录）

| 位置 | 性质 | 处理 |
| --- | --- | --- |
| `resume()` 的失败归类 | **设计缺陷**（v1.3 引入）：任何异常都变成"重新上传 512 MiB" | 七种失败分类，只有丢失/不可证明才要求重选 |
| `zipReselect` 的状态改动时机 | **事务缺陷**（v1.2 遗留）：打开文件对话框前就置 `uploading` 并清空 ZIP，用户取消后卡死 | 拆成 prepare / begin 两阶段 + 一次性 token |
| `extractArchive` 的身份校验 | **缺口**（v1.3 遗留）：`ready` 只校验长度，磁盘被替换后毫无察觉 | 每次解压前重算服务端摘要 |
| `zipBegin` 的 `openSync(file,'w')` | **覆盖风险**（v1.3 遗留）：重复 begin 会截断已上传的字节 | 幂等返回 offset；截断只在一处且需 token |
