# 06 · 数据安全与回滚

## 1. 写入路径没变

计划与批次都写进 `LibraryState`，写入口仍然只有 `Library.change()`：

```
change(action):
  ensureOpen()                     // 未挂载一律拒绝
  if (this.archiving) throw        // 导出/归档期间禁止写
  draft = structuredClone(state)   // 副本，失败不污染内存态
  result = action(draft)           // 任何 throw 都不会走到落盘
  history.prepare(draft)           // tasks/episodes 进 sqlite
  atomicWrite(library.json, snapshot)
      openSync(tmp, 'wx')          // 独占创建
      writeFileSync → fsyncSync    // 落盘
      renameSync(tmp, file)        // 原子替换
  state = history.bind(draft)      // 成功后才换内存态
```

因此：**动作抛错 → 快照不动；落盘抛错 → 内存态不换，重开读到旧快照。** 不存在"写了一半"的中间态。

## 2. 单一保存点

新增的两处跨对象不变量都在同一个 `change()` 里完成：

| 不变量 | 实现 |
| --- | --- |
| "intent 回执 = reading" ⟺ "书已进计划" | `addToPlanAtomic(keys, opts, updater)`：updater 返回 `false` 则不写计划条目，整笔回滚 |
| "切到下一本" ⟺ "记 startedAt" | `selectPlanned()`：同一 `change()` 内 `invalidate` + `selected` + `item.startedAt` |

崩溃点枚举：进程在任意两点之间死掉，重启后最多损失"这一次动作"，不会出现"读着但没排队"或"排队了但回执没写"。

## 3. 不静默丢字段

`validatePlan` / `validateBatches` 是**严格校验**，篡改即抛错，不做"尽力修补"：

- 计划：`schema != 1`、`items` 里重复 `bookKey`、`seriesId` 悬空、重复 series id、时间戳非整数、`completed` 条目缺 `bookKey` → `throw`；
- 批次：`schema != 1`、非法 id、`completed` 条目无 `bookKey`、`staged` 名不是 `<uuid>.src`、`attempts > 99`、批次时间倒流 → `throw`。

抛错发生在 `validateState()` 内，即 `open()` 阶段。结果：**打不开，而不是打开成半截数据**。既有行为一致（`validateSelection`、`validateReviews` 同样抛错）。

## 4. 迁移不覆盖原数据

`syncPlan()` 在 `open()` 的 `change()` 里执行，与 `invalidate()` 同一快照：

- 旧队列迁移只在"计划完全为空"时发生一次，且迁移后立刻清空 `selection.queue`；
- `reconcilePlan` 只把"书架上已经没有这本书"的条目移进归档，**不动任何书本数据**；
- 已完工的书进归档是幂等的（不在 `items` 里就什么都不做）。

如果 `syncPlan` 中途抛错，`atomicWrite` 不执行，`library.json` 保持原样——用户下次打开会重试同样的迁移。

## 5. 备份 / 回滚

| 能力 | 状态 |
| --- | --- |
| 导出快照 | `library.export()` / `writeArchive()` 现有实现，计划与批次随快照一起备份 |
| 恢复快照 | `library.restore(text)` / `restoreArchive(file)` 现有实现，`rollback-book-refs.json` 机制未改 |
| 单书回滚 | 既有 `book-storage` 不可变 blob + refs 回滚，本阶段零改动 |
| 降级回滚 | **有损**：旧版本不认识 `plan` / `importBatches`，会忽略并在下次写入时抹掉。回滚前必须导出备份（见 `07-已知问题与未观察项.md`） |

## 6. 暂存目录与清理

批次暂存放在既有 `transfers/batches/<batchId>/`，只允许三种文件名：`<uuid>.src`、`source.zip`、`<uuid>.import/`（worker 暂存）。

- `ImportBatches.cleanStale()`：删掉**不属于任何已知批次**的批次目录；批次目录里只清理上述形状，其他文件一律不碰；`source.zip` 一定删（上传不可能跨进程存活）。
- `ImportJob` 自己的 `cleanImportDirectory()` 未改（只认 `<uuid>.import`，拒绝符号链接、拒绝嵌套目录）。
- 成功入库后回收 `<uuid>.src`；失败/取消**保留**字节以便重试。

## 7. 与正式用户数据的关系

- 所有自动化测试都在 `mkdtempSync(join(tmpdir(), ...))` 下建库，结束 `rmSync`。
- 本阶段没有对任何真实 `dataDir`、`library.json`、`history.sqlite`、`AcquisitionRecords` 执行过写操作。
- 没有启用 GC、没有触发数据迁移脚本、没有 `git push` / `merge` / 发布 / 部署。

## 8. 越权面收敛

| 面 | 措施 |
| --- | --- |
| 模型 | 没有新增工具；计划编辑完全不经模型。协议文档明确"顺序由用户决定，你只负责报告" |
| WebUI | 计划/批次方法都要求显式 `batchId` / `itemId`；`import_batch_*` 只接受本进程创建的批次 id；`stage()` 校验连续偏移与 base64 往返 |
| 文件 | 文件名过 `safeBatchName()`（拒 `..`、控制字符、`<>:"|?*`）；ZIP 条目过既有 `zip-worker` 全套校验 |
| 停止/跳过 | 停止当前阅读必须显式 `stop: true` 且面板二次确认；普通移除当前书直接抛错 |
