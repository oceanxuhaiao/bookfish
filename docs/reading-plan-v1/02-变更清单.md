## 修改源文件

| 文件 | 改了什么 | 为什么不能更少 |
| --- | --- | --- |
| `src/library.ts` | `LibraryState` 增加 `plan` 与 `importBatches`；`validateState` 校验两者；`open()` 改调 `syncPlan`（旧队列一次性迁移 + 对账 + 已完工入库）；`selection()` 变为计划派生投影；新增计划 API（`plan` / `advancePlan` / `selectPlanned` / `planView` / `addToPlan` / `addToPlanAtomic` / `removeFromPlan` / `movePlanItem` / `placePlanItem` / `movePlanSeries` / `setPlanEnabled` / `editPlanSeries` / `planSeriesSuggest` / `updatePlanAction`）与批量导入 API（`importBatches` / `createImportBatch` / `addImportBatchItems` / `updateImportBatch` / `forgetImportBatch`） | 计划与批次必须与书架同一张原子快照，否则崩溃时会出现"读着但没排队"或"批次状态与书架不一致" |
| `src/selection.ts` | `refresh()` 不再回写 `queue`；`fulfill()` 改为 `addToPlanAtomic` 单快照写；`autoAdvance()` 变成对 `library.advancePlan()` 的薄委托；`plan()` / `abandon()` / `cancel()` / `onTaskTerminal()` 改走计划 API；`reconcileQueue()` 重写为幂等补条目 | 自选书与计划是同一件事，双写必然产生两份真相 |
| `src/status.ts` | `BookfishStatus` 增加 `plan: PlanSummary`；`LibraryPanelState` 增加 `plan` 与 `importBatches` | 模型与面板都要看到"当前 / 下一本 / 暂缓 / 缺书"，且必须是投影而不是第二份状态 |
| `src/transfers.ts` | 持有 `ImportBatches` 实例；`recover()` 清理批次暂存；`shutdown()` 先停批次 | 复用既有 `transfers/` 目录与 `ImportJob`，不新建存储 |
| `src/world.ts` | 挂载时恢复批量任务；面板 `plan` 页；批量导入 / 计划共 20 个 WebUI 方法；`status`/`get` 暴露 `plan` | UI 与模型只应有同一个入口 |
| `src/protocol/reading.md` | 新增「The single reading plan」一节，`v=3 → v=4` | 让模型知道"顺序只是呈现""五种结局不能混""当前书锁定" |
| `lib/import-worker.mjs` / `lib/zip-worker.mjs` | `scripts/build-worker.mjs` 重新构建产物（输入源未改） | 仓库把 worker 构建产物入库，跑测试即会重建 |
