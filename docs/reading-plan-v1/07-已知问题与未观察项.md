## B. 已知限制（设计取舍，不是缺陷）

| # | 限制 | 说明 |
| --- | --- | --- |
| B1 | 降级会丢计划与批次 | 旧版本不认 `plan` / `importBatches`，下次写入即抹掉。回滚前必须导出备份 |
| B2 | `selection.queue` 变成只读投影 | 任何直接写 `draft.queue` 的旧代码会失效。仓库内已全部迁移（`02-变更清单.md`） |
| B3 | 计划条目上限 200 / 归档 300 / 系列 100 | 超限计入 `overflow` 并上报，不静默丢弃 |
| B4 | 批次条目上限 100、并发 2 | 单本最多 100 MiB；整批暂存上限 1 GiB；ZIP 上限 512 MiB |
| B5 | 暂缓（`notBefore`）在队首会直接停住交接 | 有意为之：尊重用户"这周先别读这本"。代价是后面的书也不会被自动跳到 |
| B6 | 批量导入的 ZIP 文件名决定书名 | 与单文件导入一致（`detectImportMetadata`）；包内没有可信书名来源，不猜测 |
| B7 | 面板没有"拖动排序" | 用按钮（上移/置顶/插到下一本/移到最后）实现同样的结果；拖动在触屏/键盘下更难做无障碍。"拖动"在任务书里是期望交互，这里用等价的可访问控件替代 |
| B8 | 批量导入不提供"导入中逐本编辑元数据" | 预览阶段可就书名/作者整体确认，不能逐本改；需要改就单独导入那一本 |
