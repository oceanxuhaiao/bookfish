# 03 · 数据结构与迁移

## 1. 计划（`ReadingPlan`，`src/reading-plan.ts`）

```
ReadingPlan { schema:1, id, revision, createdAt, updatedAt, enabled,
              items: PlanItem[], archive: PlanArchiveEntry[], series: PlanSeries[] }
```

| 字段 | 说明 |
| --- | --- |
| `items` | **数组顺序就是阅读顺序**。只放"等待中 / 正在读"的书。索引即位置，因此移动是 O(n) 数组操作，不引入 rank/分数 |
| `archive` | 已结束的条目：`completed` / `skipped` / `removed`，带 `endedAt` 与 `reason`。上限 300，超出丢最旧 |
| `series` | 纯组织信息：`id / name / source(auto\|manual) / confirmed`。**没有任何调度字段** |
| `enabled` | 是否允许"自动按计划接着读"。关掉只影响自动交接，不动计划本身 |
| `revision` | 单调递增，每次写都 +1，供 UI 判断过期 |

**当前在读不在计划里存两份**：`PlanItem` 没有 `active` 字段，当前书由 `LibraryState.selected` 派生。这是"当前书不可被重排抢占"能自动成立的原因——不存在两个位置可以不一致。

上限：条目 200、归档 300、系列 100。超限计入 `overflow` 并上报，不静默丢弃。

## 2. 批次（`ImportBatch`，`src/import-batch.ts`）

```
ImportBatch { schema:1, id, createdAt, updatedAt, source:'files'|'folder'|'zip',
              status:'preview'|'running'|'completed'|'cancelled',
              toPlan: boolean, items: BatchItem[], error? }

BatchItem { id, name, size, status, title, author?, staged?, bookKey?, error?,
            attempts, duplicate?, duplicateOf?, group?, supported }
```

条目状态机是**单向**的：

```
pending → importing → processing → validating → completed
   ↕                                   ↘ failed
   └── needs_reselect                   ↘ cancelled
```

`setItemStatus()` 拒绝"从终态回到非终态"，一次迟到的进度回调不可能把已完成的条目打回 `validating`（这条保护来自一个真实缺陷：定时器回调与 `settle()` 竞争会把批次永久留在 `running`，现由 `src/import-batches.ts` 的 `watch()` 二次校验 + 状态机守卫共同拦住）。

批次终态只在"没有任何条目还能跑"时成立（`settleBatch()`），因此不会出现"批次说完成、条目还在解析"。

## 3. 持久化：同一张原子快照

两个新字段都在 `LibraryState` 里：

```ts
interface LibraryState {
  schema: 3;
  ...
  selection: SelectionState;
  plan: ReadingPlan;          // 新增
  importBatches: ImportBatch[]; // 新增
}
```

写入路径只有一条：

```
Library.change(draft => ...) → atomicWrite(library.json)
   openSync(tmp, 'wx') → writeFileSync → fsyncSync → renameSync
```

`tasks` / `episodes` 仍走 `history.sqlite`（`history.prepare` 生成 `$history` 引用），books 仍走 `$bookBlob` 分块 + `BookStorage` 不可变 blob。**没有新增任何存储子系统。**

批次进度按**条目粒度**落盘（进入 `processing` 一次、终态一次），上传过程中的字节不落盘索引，只落暂存文件。快照里只有书目元数据与 blob 引用，所以单次写入是 KB 级。

## 4. 打开时的三步对账（`Library.syncPlan`）

```ts
open() → change(draft => syncPlan(draft))

syncPlan(draft):
  1) 旧队列一次性迁移：plan 为空 && selection.queue 非空 → migrateLegacyQueue() → selection.queue = []
  2) reconcilePlan(draft.plan, 现存 bookKey)：书架上已删的书 → archive(status:'removed', reason:'book_removed')
  3) 已完工的书 → archive(status:'completed', reason:'completed_before_plan_advance')
  4) invalidate(draft)：取消陈旧 pending 任务与 review job
```

第 3 步是必要的：升级前就读完的书不该被当成"下一本"再交一次。

## 5. 旧数据迁移

`migrateLegacyQueue(queue, books, now)`：

| 旧 `ReadingQueueItem.status` | 迁移结果 |
| --- | --- |
| `queued` / `active` | `items`，按 `addedAt` 升序（保持用户原来的先后感） |
| `done` | `archive.status = 'completed'` |
| `cancelled` | `archive.status = 'removed'`，`reason = 'legacy_cancelled'` |
| bookKey 已不在书架 | 丢弃并计入 `dropped` |

幂等条件：`plan.items.length === 0 && plan.archive.length === 0 && selection.queue.length > 0`。迁移后 `selection.queue` 被清空，第二次打开不会再迁。

`validatePlan(undefined)`、`validateBatches(undefined)` 都返回空结构，因此**旧快照无需任何字段就能升级**；`library.json` 的 `schema` 仍是 6/7，`LibraryState.schema` 仍是 3。

## 6. `selection.queue` 降级为投影

旧代码把跨书队列存在 `selection.queue`。现在：

```ts
selection() {
  const plan = this.state.plan;
  state.queue = plan.items.map((item, i) => ({ .../ status: item.bookKey === selected ? 'active' : 'queued' }));
}
```

- 只读投影，不落盘（`selection.refresh()` 不再回写 `queue`）。
- 目的：既有 WebUI「接下来读」卡片、既有选择测试、既有 `ReadingQueueItem` 形状全部继续有效，同时只有一份真相。
- 代价（已记录）：`selection.queue` 不再是可写状态；任何仍直接写 `draft.queue` 的外部代码会失效——本仓库内已全部改完（见 `02-变更清单.md` 的测试改动）。

## 7. 单一保存点一致性

旧代码在 `fulfill()` 里"先写 intent 回执，再追加队列"。计划替换队列后如果拆成两次 `change()`，崩溃就会出现"intent 已是 reading，但书没进计划"。因此引入：

```ts
library.addToPlanAtomic([bookKey], { source:'persona', intentId }, (draft) => {
  // 在同一次 change 里同时改 selection.intents / round / 并决定是否入计划
  return shouldQueue;
});
```

失败即整体回滚（`atomicWrite` 不执行）。这条性质由 `tests/txt-acquisition-selection.test.ts` 的故障注入用例守住。

## 8. 备份与降级

- 备份：沿用 `export()` / `writeArchive()`，计划与批次随快照一起进备份；`restore()` / `restoreArchive()` 原样恢复。
- **降级是有损的**：旧版本不认识 `plan` / `importBatches`，`validateState()` 会忽略这些字段，下一次写入就把它们抹掉（书架、进度、手账不受影响）。回滚前必须 `export` 备份。这一点写在 `07-已知问题与未观察项.md`，属于已知限制而不是缺陷。
