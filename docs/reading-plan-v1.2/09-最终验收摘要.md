## 关键设计决定（复审重点）

1. **内容身份由服务端定，不由客户端定。** 前端摘要只是 `claimedSha256` 期望值；`stage()` 完成后、`launch()` 之前、ZIP `finish()` 时各算一次真实 SHA-256。同大小不同内容不再可能混进原 `itemId`。旧条目无摘要时宁可要求新建批次，也不假装验证过。
2. **ZIP 峰值用"封顶 + 实测 + 消除副本"三件套，而不是提高预算。** 所有已发布上限保持 v1.1 原值；`workspaceBytes` 只是把隐含的"ZIP + 解压树"共存占用显式化。最坏情况逐阶段写在 `03`，rename 失败回退的瞬时单条目副本也如实披露。
3. **ZIP 只在"解压完整且恢复条件满足"之后删除。** 失败保留已校验的 ZIP，重启可无感重试；这同时解决了"无操作入口的预览批次"问题（四态 + 面板入口）。
4. **"正在读"与"计划条目"分离，但不降低当前书锁定规则。** 计划外的书可见、可加回、不计入总数、不挤掉下一本；`keepReading` 与"停止切下一本"是两个不同承诺，都保留正文与进度。
5. **累计统计独立于有界窗口。** 明细仍只留 300 条（视图 50 条），但 completed / skipped / removed / truncated 不再随裁剪下降；系列解散后历史保留可读名称而非悬空 id。
6. **本轮不改持久化布局。** 文件布局仍为 8 / state 4，新字段通过 `validateStats()` / `validateBatches()` 兼容读取，旧库回填计数，不引入新的降级风险。
