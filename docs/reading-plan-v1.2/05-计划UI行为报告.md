# 05 · 计划 UI 行为报告

代码位置：`src/webui/plan.ts`、`src/webui/batch-import.ts`、`src/webui/batch-types.ts`、`src/library.ts`（`planView` / `updatePlanAction`）、`src/world.ts`（分发）。测试：`tests/webui/plan-panel.test.ts`（15 例）、`tests/webui/batch-import.test.ts`（8 例）、`tests/plan-display.test.ts`（7 例）。

## 1. "正在读"卡片的两个真相

| 字段 | 来源 | 含义 |
| --- | --- | --- |
| `plan.reading` | `LibraryState.selected` | **当前实际正在读的书**，可能不在计划里 |
| `plan.current` | `ReadingPlan.items` 中 `active` | **当前正在执行的计划条目** |

渲染优先级：`reading` 存在 → 展示真实书名、进度、章节；`reading` 为空但 `current` 存在 → 展示计划条目并注明"排到了但还没被选中阅读"；两者都空 → 显示"现在没有在读的书"。

`reading.inPlan` 决定徽标：

- 在计划内：`第 N / M 位 · 已读 X%`，并说明"这本书读完之前不会被重排挤掉"。
- 计划外：`计划外 · 已读 X%`，并说明"不计入计划本数，也不会挤掉计划里的下一本"；额外显示章节名与**「把这本书加进计划」**按钮（`plan_add` + 刷新）。

空态判定从 `!plan.total && !plan.completedCount` 改为 `!plan.total && !plan.reading`：**计划为空但正在读一本计划外的书时，不再提前返回空计划界面**。

进度单位按 `progressUnit` 显示（章节 / 字符），不用计划条目的进度冒充真实进度。

## 2. 两个不同的"离开"操作

| 按钮 | 载荷 | 结果 |
| --- | --- | --- |
| 停止读这本，改读下一本 | `{ action:'remove', itemId, status:'skipped', stop:true, reason:'stopped_by_user_in_panel' }` | 归档为 skipped + 失效当前任务 + 切到下一本；正文、进度、手账、读后感保留；带危险确认 |
| 移出计划，继续读这本 | `{ action:'remove', itemId, status:'removed', keepReading:true, reason:'removed_but_still_reading' }` | 只离开计划，`selected` 不变，仍是当前在读书；进度与手账保留；带确认 |

`Library.updatePlanAction()` 现在把 `keepReading === true` 透传（v1.1 漏传），所以第二个按钮真正生效。两种操作都**不降低当前书锁定规则**、不删除书架原件。

**没有可读的下一本时**：stop 按钮 `disabled`，并在下方给出解释——"没有其他可读的下一本，所以不能'换下一本'。如果你只想让它离开计划但仍继续读这本，用下面的按钮。" 可读下一本的计算过滤 `active / complete / !present / notBefore > now`，暂缓书籍不会被绕过。

## 3. 错误提示不再静默

- 页面顶部新增 `<p class="plan-error">`，默认 `hidden`。
- `act()` 从 `void run().catch(() => undefined)` 改为 `void run().catch(report)`；每次点击先清空旧错误，成功不显示，失败把 `error.message` 原样展示。
- 覆盖：排序失败、系列操作失败、持久化失败、无下一本时的服务端拒绝、网络/调用异常。
- 不允许所有按钮统一吞异常，也不把技术栈信息直接甩给用户——`report()` 展示的是服务端已人话化的 `message`。

## 4. 历史策略可见

摘要行从"已完成 N 本"改为"**累计读完 N 本**"，避免与 300 条窗口混淆。新增一行说明：

```
历史只保留最近 300 条（当前 N 条），更早的 X 条已不再列出，但累计数量仍然计入；跳过 Y 本、移出 Z 本。
```

`X = truncatedCount` 为 0 时不显示该分句；`skippedCount / removedCount / archiveLimit / archiveKept` 均来自 `planView()` 的累计统计字段。

## 5. 批量导入 / ZIP 面板

`ImportBatchZipView` 增加 `zip?: { name, size, state, sha256?, peakBytes? }`；`status(batchId)` 透传。面板按 `state` 展示：

| 状态 | 用户看到 | 可用操作 |
| --- | --- | --- |
| `uploading` | 正在上传（含进度） | 继续分片 |
| `needs_reselect` | 需要重新选择 ZIP | 「重新选择 ZIP」→ `import_batch_zip_reselect`，同 batchId 重传 |
| `ready` | 上传完成待解压 | 自动重试解压（重启后由 `resume()` 触发） |
| `extracted` | 已完成解压 | 正常派发导入；可取消旧批次记录（不删书） |

面板显示实测 `peakBytes`（若有）与声明大小，便于核对真实峰值。前端 `fileDigest()` 只对 ≤64 MiB 文件计算期望摘要，超出时留空由服务端计算——**前端摘要永远只是 `claimedSha256`，不是身份判定依据**。

## 6. 行为回归矩阵

| 场景 | 期望 | 证据 |
| --- | --- | --- |
| 升级后当前书未进计划 | 显示计划外 + 真实进度 + 加回按钮 | `plan-display` 5 例 + `plan-panel` |
| 移出计划但继续读 | `reading` 仍在，标记计划外 | `plan-display`「keeps a removed-but-still-read book in the reading slot」 |
| 计划为空但在读书 | 不返回空态 | `plan-display`「keeps the current book visible when the plan is empty」 |
| 当前书完读无下一本 | 仍展示已完读的当前书 | `plan-display`「still shows a finished current book that has no successor」 |
| 无下一本时点停止 | 按钮禁用 + 解释，不产生意外推进 | `plan-panel` 用例 |
| 排序 / 系列 / 持久化失败 | `.plan-error` 显示原因 | `plan-panel` 用例 |
| ZIP 中断重启 | 面板出现重新选择入口，同 batchId | `webui/batch-import` 用例 + `import-batch-identity` |
| 同大小不同内容 ZIP | 拒绝，批次转 `needs_reselect` | `webui/batch-import` + `import-batch-identity` |
