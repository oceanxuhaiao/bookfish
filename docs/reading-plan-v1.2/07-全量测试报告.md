## 4. 首个全量回归发现的 3 个失败（已修复）

第一次跑全量时 `2 failed | 116 passed`，3 个失败**都不是产品缺陷**，而是新增字段让既有断言的 `toEqual` 严格比较失配：

| 失败 | 根因 | 修法 |
| --- | --- | --- |
| `import-batch-budget`「pins every ceiling the task book names」 | `DEFAULT_BATCH_BUDGET` 新增 `workspaceBytes` | 断言升级为包含 `workspaceBytes: 1536 MiB`，并**新增断言** `workspaceBytes === zipBytes + batchBytes`，把"工作集恰等于两份之和、未放大预算"钉死 |
| `import-batch-run`「recovers an interrupted batch…」 | `resume()` 返回值新增 `archives` | 断言升级为 `{ resumed: 1, reselect: 0, archives: 0 }` |
| `import-batch-run`「marks an interrupted batch for reselect…」 | 同上 | 断言升级为 `{ resumed: 0, reselect: 1, archives: 0 }` |

`archives > 0` 的正向场景由 `import-batch-identity`「reports an interrupted archive upload after a restart and can reopen the same batch」的 `expect(report.archives).toBeGreaterThanOrEqual(1)` 覆盖。修复后重跑全量：exit 0，118 files / 1281 passed | 1 skipped。

## 5. 本轮修掉的真实缺陷（开发过程中）

| 缺陷 | 表现 | 修法 |
| --- | --- | --- |
| 错误 `claimedSha256` 锁死批次 | 重选后声明摘要仍不符，`zipFinish()` 反复拒绝 | reject 时清除错误 claim，保留 `needs_reselect` |
| ZIP 条目摘要未透传 | `addItems()` 丢弃 `sourceSha256/sourceName` | 修正 `RawInput` 与 `addItems()` |
| ZIP 面板在 jsdom 无法启动 Worker | 端到端测试挂起 | 面板测试验证同 batchId 重传与服务端 `sha256`；真实解压峰值交给 Node 环境用例 |
| 空 ZIP 批次标题显示为"导入 等 0 本" | 上传中断、条目为 0 | `batchSummary()` 用 `zip.name` 命名 |
| 前端期望摘要可能把批次写死 | 客户端摘要与服务端不符 | 服务端 `sha256File()` 重新计算；声明值只作比对 |
