## 六个必须看的结论

1. **重新选择文件校验内容身份，不再只比大小。** `BatchItem.sourceSha256` / `sourceName` 持久化；服务端用 256 KiB 流式 SHA-256 计算，不信任前端传入的摘要；`reselect()` 校验大小、名称、原始相对路径与摘要；`launch()` 进 `ImportJob` 前再重算一次暂存文件摘要。旧批次没有可信摘要时**明确拒绝猜测**，要求新建批次并保留原证据。
2. **ZIP 真实磁盘峰值有硬上限。** 解压产物用同盘 `renameSync` 转成 `.src` 暂存文件，不再复制第二份；`batchDirBytes()` 实测峰值并写入 `zip.peakBytes`；`workspaceBytes = zipBytes + batchBytes = 1536 MiB` 在继续写入前拒绝。**没有提高任何已发布上限**，判定理由见 `01` / `03`。
3. **ZIP 上传四态状态机 + 明确恢复入口。** `uploading → needs_reselect → ready → extracted`；`zipBegin/zipChunk/zipFinish` 严格校验声明长度、连续 offset、完整 SHA-256；重启后 `resume()` 把半截上传暴露为"重新选择"，`zipReselect()` 尽量复用原 `batchId`；已完成解压的 ZIP 才删除。
4. **`reading` 与 `current` 分离。** 当前实际在读书由 `LibraryState.selected` 派生，计划内 active 条目由 ReadingPlan 派生；"正在读 · 计划外"显示书名与真实进度、不计入计划总数、不改变下一本顺序；计划为空但在读书时不再提前返回空态。
5. **`keepReading` 真正可用，UI 失败不再静默。** `updatePlanAction()` 透传 `keepReading`；"停止读这本，改读下一本"与"移出计划，继续读这本"分离；无下一本时禁用 stop 并解释原因；所有按钮共用 `.plan-error` 错误条展示异常。
6. **累计阅读统计不随归档截断而失真。** `PlanStats` 独立保存 completed / skipped / removed / truncated；归档窗口仍是 300 条；`dropUnusedSeries()` 保留 `seriesName` 并清掉悬空 `seriesId`；旧计划自动回填计数。
