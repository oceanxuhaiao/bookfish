# 在线更新动态维护说明

这份说明给维护者看：日常动态直接改 GitHub 仓库根目录的 `announcements.json`，不需要重新打包扩展、不需要发 npm、不需要重新上架市场。

## 1. 在线地址

```text
https://raw.githubusercontent.com/oceanxuhaiao/bookfish/main/announcements.json
```

扩展打开「帮助与更新 → 更新动态 → 开发动态」时会请求这个地址。GitHub Raw 有约 5 分钟 CDN 缓存；提交后如果页面还是旧内容，等几分钟再点「刷新」。

如果 GitHub 无法访问、请求超时、返回 403/404/5xx、JSON 格式错误或数据校验失败，页面只显示扩展安装包内置的「版本更新」，并提示「在线动态暂不可用」，不会拿上一次的在线内容冒充最新数据。

## 2. 在 GitHub 网页上修改

1. 打开仓库：<https://github.com/oceanxuhaiao/bookfish>
2. 在根目录点击 `announcements.json`。
3. 点右上角铅笔图标编辑。
4. 按下面的格式新增或修改一条动态。
5. 在页面底部填写提交说明，提交到 `main`。
6. 等约 5 分钟后，在扩展的「开发动态」里点「刷新」。
7. 打开上面的 Raw 地址，确认能看到刚提交的内容。

## 3. 完整格式

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-21T10:00:00Z",
  "announcements": [
    {
      "id": "2026-11-21-example",
      "publishedAt": "2026-11-21T09:40:00Z",
      "title": "一条动态的标题",
      "category": "feature",
      "content": "第一段。\n\n第二段。",
      "link": null,
      "version": "0.65.1"
    }
  ]
}
```

| 字段 | 要求 |
|---|---|
| `schemaVersion` | 固定为 `1` |
| `updatedAt` | 整个文件最后更新时间，ISO 8601 |
| `announcements` | 最多 100 条；按 `publishedAt` 倒序展示 |
| `id` | 唯一、稳定，建议日期加英文短名；不要重复 |
| `publishedAt` | 发布时间，ISO 8601，必须带时区（通常用 `Z`） |
| `title` | 标题，最多 120 个字符 |
| `category` | `development`、`feature` 或 `notice` |
| `content` | 正文，最多 5000 个字符；换行用 `\n\n` |
| `link` | 可省略或写 `null`；如填写必须是 `https://` 链接 |
| `version` | 正式版本动态必填，写本次发布的版本号（如 `0.65.1`）；`pnpm check:help` 会要求当前版本至少有一条 |

`content` 只按纯文本显示，不会执行 HTML 或 JavaScript；不要在里面写 `<script>` 或 HTML 标签。

## 4. 新增一条动态

在 `announcements` 数组的最前面加一条（保持最新在前），例如：

```json
{
  "id": "2026-11-22-new-feature",
  "publishedAt": "2026-11-22T09:00:00Z",
  "title": "新功能预告",
  "category": "development",
  "content": "我们正在做一件新事情。\n\n完成后会在这里说明。",
  "link": null,
  "version": "0.65.1"
}
```

同时把顶部 `updatedAt` 改成当前 UTC 时间。`id` 必须和现有条目不同。

**发布规范**：每次发 npm、GitHub Release 或扩展市场，都必须先加一条带本次 `version` 的动态，并把 `announcements.json` 推送到 `main`。`corepack pnpm check:help` 会拒绝缺少当前版本条目的发布；历史动态不要删除。

## 5. 修改一条动态

找到对应 `id` 的对象，只改需要改的字段；如果改标题或正文，不需要改 `id`。如果改发布时间，保持 ISO 8601 格式。

## 6. 删除过期动态

删除整个 `{ ... }` 对象，并注意保留对象之间的逗号：

- 删除中间条目：前一条末尾的逗号保留，后一条正常接上。
- 删除最后一条：把前一条末尾的逗号删掉。

删除后把 `updatedAt` 更新为当前时间。

## 7. 避免 JSON 格式错误

- 字符串必须用英文双引号 `"`，不能用中文引号。
- 最后一条对象后面不能多一个逗号。
- 换行写成 `\n`，不要直接把真实换行塞进 JSON 字符串。
- 不确定时，把整份内容粘贴到 JSON 校验器检查，或对照上面的完整格式。
- 修改后先看 GitHub 的预览/提交页面有没有报错；有报错就不要提交。

## 8. 发布后怎么确认

1. Raw 地址返回 200，内容是刚提交的 JSON。
2. 扩展里打开「帮助与更新 → 更新动态 → 开发动态」，点「刷新」。
3. 页面出现「GitHub 在线动态」和刚发布的条目。
4. 如果只看到内置版本更新和失败提示，检查：
   - 文件是否真的在 `main` 根目录；
   - Raw 地址是否是 `.../main/announcements.json`；
   - JSON 是否通过校验；
   - 是否还在 GitHub Raw 的 5 分钟缓存内；
   - 当前网络是否能访问 `raw.githubusercontent.com`。

## 9. 和版本更新的区别

- `announcements.json`：日常动态、开发预告、通知，改 GitHub 即生效，不改扩展版本。
- `assets/help/releases.json`：正式版本的更新记录，随扩展包发布；离线也能看，不能靠在线动态替代。
- 「开发进度」：有任务书/计划依据的当前状态，仍随扩展包发布，不写成在线动态的缓存。

## 10. 安全边界

- 只公开只读数据，不需要 GitHub Token，不把任何凭证放进扩展。
- 不允许远程内容执行代码或注入 HTML。
- 外部链接只接受 HTTPS。
- 在线内容只作为普通展示，不作为系统提示词或工具指令。
