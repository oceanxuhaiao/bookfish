# 04 · 调度与原子性说明

## 1. 没有第二套调度器

```
ReadingScheduler ──(idle 30s / 无 active / 无 cognition / 未达日章目标 / 非 rest·routine)──▶ hooks.autoAdvance
                                                                                              │
                                                                          SelectionCoordinator.autoAdvance()   ← 薄委托
                                                                                              │
                                                                          Library.advancePlan(scheduler.status())
                                                                                              │
                                                                                PlanCoordinator.attempt()
                                                                                              │
                                                     ┌────────────────────────────────────────┴───────────────────────────┐
                                          current.complete?                          nothing selected?
                                                     │                                        │
                                     Library.completeCurrentPlanned(key,{switch})      Library.startPlanned()
                                       = 归档 + 失效 + 切书 + startedAt（一次 change）    = 选第一本可读（一次 change）
```

`PlanCoordinator` 的能力边界（全文 ~95 行）：

- ✅ 读 `library.status()` / `plan()` / `hasPendingReviewJob()`
- ✅ 调 `completeCurrentPlanned()` 或 `startPlanned()`
- ❌ 不读正文、不建 task、不写 frontier、不确认、不写手账/读后感/故事记忆

进度仍然只有 `readNext` / `finish` / `finishMany` 三条写入路径。

## 2. 门禁分层：切换 vs 记账

这是本轮最重要的语义变化。

| 性质 | 归属 | 受门禁影响？ |
| --- | --- | --- |
| **归档**（把完读条目移入 archive） | 记账 | ❌ 不受影响。只要真完读就归档 |
| **切换**（换 `selected` + 写 `startedAt`） | 阅读动作 | ✅ 受全部门禁影响 |

结果：暂停 / 睡眠 / 用餐 / 休息 / 读后感 pending / 计划关闭时，计划依然如实显示"这本读完了、还剩几本"，只是不换书。门禁打开后同一次调用补上切换。这样 `completedCount` 永远不需要等下一次重启才对。

门禁与返回原因：

| 顺序 | `reason` | 条件 |
| --- | --- | --- |
| 1 | `not_mounted` | 库未挂载 |
| 2 | `current_incomplete` | 有当前书且未读完 |
| 3 | `pending_text` | 有已发出未确认的正文 |
| 4 | `paused` | 用户暂停 |
| 5 | `routine` | 睡眠/用餐 |
| 6 | `resting` | 休息中 |
| 7 | `review_pending` | 当前书 review job 仍 pending |
| 8 | `plan_disabled` | `plan.enabled === false` |
| 9 | `deferred` | 队首 `notBefore` 未到（**不越位**） |
| 10 | `plan_exhausted` / `plan_empty` | 无可读条目 / 空计划 |

第 4–7 条都发生在"归档之后、切换之前"，因此它们不会阻止归档。第 9 条同理。

## 3. 原子性：三个单点提交

| 场景 | 提交内容 | 崩溃后果 |
| --- | --- | --- |
| 完读交接 | 归档 + `invalidate` + `selected` + `startedAt` | 整体回滚，下次 tick 重做同样决定 |
| 停止当前书 | 归档 + `invalidate` + `selected` + `startedAt` | 整体回滚，条目仍在计划里、仍在读，可安全重试 |
| 自主选书入队 | intent 回执 + 计划条目 | 整体回滚，回执与条目不会单独存在 |

"没有下一个可读"的情况**不进 change**：`removeFromPlan(stop)` 在提交前就抛错，因此不可能出现"条目已归档但选择没变"的中间态。`nextReadable()` 在 `draft` 上重算一次，保证两次判断一致（预检只是快速失败，真正的裁决在事务内）。

## 4. 当前书锁定规则

| 操作 | 规则 |
| --- | --- |
| `move` / `place` 当前书所在条目 | 抛 `The book being read is locked` |
| `move` / `place` 其他条目 | 落点下限 `activeIndex + 1`，"置顶"= 紧随当前书 |
| `move_series` 含当前书 | 拒绝 |
| `remove` 当前书（无 `stop`） | 抛 `locked` |
| `remove` 当前书（`stop: true`） | 原子归档+切换；无下一本则拒绝 |
| `remove` 已完读条目 | 抛 `already finished`（只能记 completed） |

## 5. 与既有自选书门禁的接缝

| 旧行为 | 新行为 |
| --- | --- |
| `fulfill()` 追加 `selection.queue` | `addToPlanAtomic([key], {intentId}, updater)` 一次快照写完回执与条目 |
| `plan(intentId,'defer')` 改 queue 行 | 计划里有条目就 `setItemNotBefore`，否则 `addToPlan({notBefore})` |
| `abandon`/`cancel` 把 queue 行标 cancelled | `removeFromPlan(..., {status:'removed', keepReading:true, reason})` |
| `reconcileQueue()` 重建 queue | 对 `queueOnImport` 且非终态 intent 幂等补条目 |
| `onSelectionChanged()` 标 active | 只 `refresh()`；active 由 `selected` 派生 |

`selection.queue` 现在是只读投影，且**过滤掉已完读条目**——完读的书不会再被当作"接下来读"。

## 7. 自动切书的可观察后果（本轮更新）

| 场景 | 结果 |
| --- | --- |
| 读完 A，计划里有 B | 下一次 idle 断言：A 进 archive，B 被选中并写 `startedAt` |
| 读完 A，计划里没有 B | A 照样进 archive，`completedCount +1`，`selected` 保持 A |
| 读者暂停时 A 读完 | A 进 archive；不切书；恢复后切到 B |
| A 的读后感 job 还 pending | A 进 archive；不切书；job 终态失败后切到 B |
| B 被暂缓 | 不切、不越位，`deferred` |
| B 已下架 | 跳过 B 继续找；打开库时 B 已被 `reconcilePlan` 归档 |
| 重复完读回调 | 不再二次归档；第二次因当前书未读完返回 `current_incomplete` |
| 用户在交接前重排 | 以用户顺序为准（`plan-combination` 用例） |
