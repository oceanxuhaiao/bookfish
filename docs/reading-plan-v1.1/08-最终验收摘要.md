## 关键设计决定（复审时请重点看）

1. **归档与切换共用一次提交，但归档不看门禁。**
   计划要如实反映"读完了"，所以暂停/作息/读后感 pending 时照样归档；只是不换书。这解决"计划状态与真实状态不一致"，又没降低切换门槛。

2. **没有下一本时，拒绝停止，而不是留下一个"在计划外仍在读"的书。**
   这是本轮语义上最明显的改变，替代路径是 `keepReading: true`（面板"移出计划（继续读这本）"）。理由是审核把"已移出计划却仍被当成正常在读书"列为不可接受状态，而拒绝是唯一能**从结构上**消灭它的做法。

3. **降级保护落在文件布局而不是 state 版本。**
   state 版本不落盘（`hydrate` 把 4/5/6/7 都映射成 3），只改它旧版本照样能打开并覆盖。因此把布局提升到 8，让旧版本在 `validateState` 直接抛错。代价是降级期间库不可用。

4. **预算与完整性都在服务端、都在写盘前。**
   前端只是提示；绕过面板直接调 `stage()` 一样会被拒。

5. **持久化仍然只有一个快照。**
   计划与批次是 `LibraryState` 的字段，写入口只有 `Library.change()`；没有新增 WAL/GC/分段存储。
