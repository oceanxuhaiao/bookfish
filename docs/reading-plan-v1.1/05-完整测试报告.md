## 4. 本轮修掉的真实缺陷

| 缺陷 | 表现 | 修法 |
| --- | --- | --- |
| `reselect` 后批次不重启 | 唯一条目重选后批次仍是 `completed`，`pump()` 拒绝派发，条目永远 `pending` | `reselect()` 内把 `draft.status` 置回 `running` |
| `stage()` 结束时立即 `pump()` 会与上传竞争 | 重选后刚 `reselect` 就派发，此时字节还没上传 → 又判 `needs_reselect` | 只在**最后一片**落盘后 `pump()`；`launch()` 仍复核真实长度 |
| `openSync(file,'r+')` 对新建文件失败 | 首个分片报 `Cannot open the import staging file` | 首次写入用 `'w'`，其余 `'r+'` |
| `normalizeInputs` 对 >100 个输入直接抛错 | 用户拿到"一次最多 100 个文件"而不是溢出计数 | 请求上限放宽到 400，批次仍由 `addBatchItems` 报 `overflow` |
| 预算只校验单文件 | 100 本小文件可绕过 | 增加"整批声明总量"校验 |
| state 版本不落盘导致降级保护无效 | 改 state 版本号旧版本仍能打开 | 改为提升文件布局版本到 8 |
| 单本入队后计划页不刷新 | 详情页点"加入阅读计划"看不到变化 | 写入后重新取 `get` 再渲染 |

测试层面的两个坑（不是产品缺陷，但会让结论失真，已修正）：

- 异步谓词直接放在 `if (predicate())` 里恒为真 → `waitFor` 秒过；改为 `await predicate()`。
- 用文本 `includes('重新选择文件')` 判断详情已渲染，实际匹配到了历史行的"N 本需重新选择文件"；改为等详情里出现《书名》。
