# 03 · 最终数据结构与迁移说明

## 1. 两个版本号，不要混

| 版本号 | 含义 | 位置 | 当前值 |
| --- | --- | --- | --- |
| **文件布局 schema** | `library.json` 的物理布局（books 引用形式、history 引用、是否含新字段） | 文件顶层 `schema` | **8** |
| **state 形状 schema** | `LibraryState` 的字段集合 | 文件顶层 `schema`（由布局映射） / 内存态 | 4 |

映射关系（`src/book-storage.ts` `hydrate()`）：

```
文件 schema 8            → state 4
文件 schema 4,5,6,7      → state 3
其他                     → 原样透传（随后被 validateState 拒绝）
```

为什么不用 state 版本做降级保护：state 版本**不落盘**，旧版本会把任何它认识的布局一律读成 state 3。只有文件布局版本能被旧版本看见，所以 fail-closed 必须落在布局上。

## 2. 计划（`ReadingPlan`，`src/reading-plan.ts`）

```
ReadingPlan { schema:1, id, revision, createdAt, updatedAt, enabled,
              items: PlanItem[], archive: PlanArchiveEntry[], series: PlanSeries[] }
```

| 字段 | 说明 |
| --- | --- |
| `items` | **数组顺序 = 阅读顺序**。只放"等待中/正在读"。移动是数组操作，不引入 rank |
| `archive` | `completed / skipped / removed` + `endedAt` + `reason`，上限 300 |
| `series` | `id / name / source(auto\|manual) / confirmed`，**没有调度字段** |
| `enabled` | 是否允许"自动按计划接着读"，关掉不影响计划本身 |
| `revision` | 单调递增，每次写 +1 |

**当前在读不存在计划里**：由 `LibraryState.selected` 派生。这是"当前书不可被抢占"能自动成立的原因。

上限：条目 200 / 归档 300 / 系列 100，超限进 `overflow` 不静默丢。

本轮新增的归档规则：完读时 `archiveItem(..., 'completed', now, 'finished_while_planned')`，由 `Library.completeCurrentPlanned()` 在交接的同一次提交里写入。

## 3. 批次（`ImportBatch`，`src/import-batch.ts`）

```
ImportBatch { schema:1, id, createdAt, updatedAt, source:'files'|'folder'|'zip',
              status:'preview'|'running'|'completed'|'cancelled',
              toPlan, items: BatchItem[], error? }
BatchItem  { id, name, size, status, title, author?, staged?, bookKey?, error?,
             attempts, duplicate?, duplicateOf?, group?, supported }
```

条目状态机单向：

```
pending → importing → processing → validating → completed
   ↕                                   ↘ failed
   └── needs_reselect                   ↘ cancelled
```

`setItemStatus()` 拒绝"终态 → 非终态"，迟到的进度回调不可能把已完成条目打回 `validating`。
`needs_reselect` 与 `cancelled` 都保留 `staged` 语义：前者可 `reselect`，后者可 `retry`。

批次终态只在"没有任何条目还能跑"时成立。

## 4. 持久化：仍然是同一张原子快照

```ts
interface LibraryState {
  schema: 4;                 // LIBRARY_STATE_SCHEMA
  ...
  selection: SelectionState; // 旧的跨书队列，现在是只读投影
  plan: ReadingPlan;
  importBatches: ImportBatch[];
}
```

写入口只有 `Library.change()`：

```
draft = structuredClone(state)
result = action(draft)                      // 抛错即整体不提交
history.prepare(draft)                      // tasks/episodes → history.sqlite
atomicWrite(library.json, { ...prepare(draft), schema: 8, tasks: [], episodes: [], $history })
   openSync(tmp,'wx') → writeFileSync → fsyncSync → renameSync
state = history.bind(draft, ref)
```

没有新增任何存储子系统；批次暂存复用既有 `transfers/batches/<batchId>/`。

## 5. 旧数据迁移

### 5.1 v0.66.7（布局 6/7，state 3）→ 本轮（布局 8，state 4）

- `validateState` 接受 state 1–4，全部产出 4；
- 缺 `plan` → `validatePlan(undefined)` → 空计划；
- 缺 `importBatches` → `validateBatches(undefined)` → `[]`；
- 第一次写入即变成布局 8。

`tests/schema-downgrade.test.ts`「still opens a v0.66.7 snapshot and upgrades it on the next write」把一份真实快照改写成"布局 6 + 删掉 plan/importBatches"来验证，进度与书都完好。

### 5.2 旧跨书队列 → 计划（一次性）

`syncPlan()`：仅当 `plan` 为空且 `selection.queue` 非空时，`migrateLegacyQueue()` 按 `addedAt` 升序建条目，`done → archive completed`，`cancelled → archive removed`，书架已无的书丢弃并计数。迁移后清空 `selection.queue`。

### 5.3 打开时的对账（每次）

```
syncPlan(draft):
  1) 旧队列一次性迁移（条件见上）
  2) reconcilePlan：书架已删的书 → archive(removed, 'book_removed')
  3) 已完工的书 → archive(completed, 'completed_before_plan_advance')
  4) invalidate：取消陈旧 pending 任务与 review job
```

第 3 步必要：升级前就读完的书不该被当成"下一本"再交一次。

## 6. 备份 / 恢复 / 降级

| 能力 | 状态 |
| --- | --- |
| JSON 导出/恢复 | `export()` / `restore()`，计划与批次随快照 |
| 归档导出/恢复 | `writeArchive()` / `restoreArchive()`，归档内层 schema 现为 8 |
| 降级到 v0.66.7 | **拒绝打开**（`Unsupported or invalid library state`），不会静默丢字段 |
| 升级提交失败 | `library.json` 字节不变（有 SHA-256 对比用例） |

降级代价：旧版本无法使用整个库，而不是丢一部分数据。这是审核明确允许的选项，也是本仓库唯一能做到的 fail-closed 方案。回滚流程：用新版本 `export()` 出备份 → 回滚二进制 → 若旧版本必须读，需先用旧版本重建库（等于放弃计划/批次），因此**回滚前的导出是强制步骤**。

## 7. 不静默丢字段

`validatePlan` / `validateBatches` 是严格校验：重复 `bookKey`、悬空 `seriesId`、`completed` 条目缺 `bookKey`、`staged` 名不合法、时间戳倒流……一律抛错。抛在 `open()` 里，结果是**打不开**，而不是打开成半截数据。
