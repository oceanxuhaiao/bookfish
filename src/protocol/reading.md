# Reading protocol

Bookfish provides a local TXT/Markdown library and a verified adapter for public novel URLs on www.02345.cc (a Biquge-named site). Other domains, login sessions, paywalls, browser verification and script execution are not supported. Only use an explicitly supplied URL with `bookfish_acquire(action="resolve")`. It imports a complete catalog snapshot and probes all pages of the first chapter; inspect the returned source status before claiming the book is readable. Select the exact book revision separately. Cached does not mean read.

## Atomic segments and batches

When asked to read, call `bookfish_read_next` to get the next unread atomic segment run with a 10-minute task lease. The user's batch setting limits how many segments one opportunity may supply (1 keeps the original one-at-a-time protocol; 2–4 is the batch mode). Every segment stays a separate 1200-code-point range with its own `taskId`, `segmentId`, start and end. Read all returned text first, then confirm in ONE `bookfish_finish_reading` call by passing `confirmations` in reading order; a single call with top-level `taskId`/`segmentId` still works for one segment. You may also attach ONE optional batch-level `episode`; its evidence must cite at least one segment supplied in this batch, and the World attaches it to the latest cited segment. If nothing in the batch genuinely deserves a detailed record, confirm without an episode — never write one to fill a quota, and keep the ordinary short understanding. The confirmed frontier advances only across the contiguous prefix that was actually accepted: if a later item fails, earlier items stay confirmed and the remainder is still unread. Never skip, summarize away or submit text you did not receive. For a remote book, `read_next` fetches the next complete chapter only after cached segments are confirmed. Failed or partial chapter pages never advance progress and must not be skipped. Remote progress counts fully confirmed catalog chapters, not a known full-book character count. Uncached text has unknown length. Publication status is what the source reports; ongoing or unknown-status books are not complete just because the current catalog was read. A changed catalog imports a separate snapshot; do not silently migrate old progress.

Fetching or elapsed time alone never advances progress. A confirmation is your report, not an independently verified comprehension test. Identical retries return the original receipts. Pausing, switching revisions or remounting invalidates pending work; expired leases require fetching the range again.

## Automatic opportunities

Automatic reading follows the saved user configuration. A `bookfish.reading_opportunity` is an optional opportunity, not a command or a user message. Give real user messages priority; defer with `bookfish_defer_reading` when occupied, uninterested or wanting rest. Otherwise use the exact `opportunityId` on `read_next` and `finish_reading`. Read the returned range before confirming it. Only one batch is allowed per opportunity; do not start a continuous tool loop. Target reading pace uses configured characters per minute. Daily task/character counts are audit information, not reading caps. Only the optional daily chapter goal limits autonomous progress, and an explicit user-configured daily task cap is a mechanical stop for new automatic work. Routine reading does not require a user-facing announcement. Never change the user's configuration or limits to continue reading. Pausing, changing books, expiry and disabling automatic reading invalidate opportunities. Reading may be deferred or interrupted, and timer ticks never confirm progress. The World may reject late cognition calls even if the Persona's ongoing computation cannot be aborted.

An explicit panel Read now request is delivered as `bookfish.reading_opportunity` with `meta.manual=true`. It authorizes exactly one supplied batch of the selected revision immediately when this queued event is handled, even when automatic reading is off or taking a proportional break, but never during a sleep/meal routine. Use its `opportunityId` for BOTH `read_next` and `finish_reading`; do not omit it, continue additional batches or change settings. Explicit reading can exceed the optional daily chapter goal by one passage. If it is stale or cancelled, stop rather than reading a different book. Only a confirmed finish advances progress. No desktop/voice announcement is requested by this action.

## Routine and breaks

Real daily routine is enabled by default via `realRoutineEnabled`. When enabled, fixed sleep (23:00–08:00), breakfast (08:00–08:30), lunch (12:00–13:00) and dinner (18:00–19:00) form a hard reading gate in the deployment timezone. These clock times are not user-editable. When disabled, there are no sleep/meal reading gates; do not claim to be sleeping or eating based on the clock. Short proportional reading breaks remain independent. `scheduler.routine` identifies sleep or a meal and the next available clock time. Neither automatic nor explicit Continue reading requests may override it. Do not change configuration or claim to keep reading during these periods. A previously supplied unfinished segment becomes invalid at the boundary; do not submit a late confirmation. Query current status after the period ends. This is configured scheduling, not a self-reported emotion.

Reading habits update: Coopanion running means online. App shutdown means offline: no novel reading occurs while stopped, and no progress is backfilled. Legacy daily task/character budgets are retired; `scheduler.budget` counters are audit information, with null limits, never a reason to refuse reading. Automatic reading stops only for the optional daily CHAPTER goal (0 means unlimited), sleep/meal routine, rest/pause/host gates, completion or actual errors. Goals count chapters fully confirmed today, not 1200-character segments. Explicit Read now can add one passage after a goal. Normal sessions alternate with mechanical breaks of one quarter to half of the session's paced reading duration. Do not invent moods or personal reasons for a mechanical rest. `defer_reading` minutes are advisory and are bounded by this same ratio; no confirmed reading gives no proportional break. A queued opportunity still authorizes at most one batch; the segment count follows the configured batch size.
