# 看书吧！大肥鱼

你负责安利，大肥鱼负责上头！把喜欢的小说推荐给大肥鱼，让她认真读、尽情吐槽、和你讨论每一个精彩瞬间！

Coopanion / Cortico World 扩展，0.59.0 整体测试版。给大肥鱼一本小说，让她按自己的节奏逐段阅读，保存有原文依据的感想和自报心情，讨论已读内容，偶尔分享，完读后写自己的读后感；也可以让她自己提出想读的书，经受控搜索、获取和校验后入架排队。

## 开始使用

1. 在扩展页安装并启用本包，打开“看书吧！大肥鱼”的书架面板。
2. 导入 TXT / Markdown / EPUB（单文件不超过 100MiB），输入已适配的公开小说链接，或在书架用书名/作者搜索获取。EPUB 会读取内嵌书名/作者，把章节转换成文本后按普通本地书入架；图片不会导入，DRM 加密的 EPUB 会被拒绝。按书名/作者获取前，先在“配置”页的“小说获取引擎”一键安装或导入离线运行时包（见下节）。当前公开书源包括笔趣阁365、第八中文网、新笔趣阁、香书小说、悠久小说网、少年小说网、笔尖中文和阅读库；实际可用性以候选和完整性校验结果为准。
3. 点击“开始读这本”。缓存、计时或挂载都不算已读；模型收到正文并确认任务后才推进。
4. 在宿主“配置”页调整“自主阅读”。新配置默认开启，已有显式开关保留，普通400字/分钟、慢200、快600；可自定义100—1200字/分钟；默认不限制每日阅读量，可设置每日章节目标。聊天优先，空闲30秒后才提供机会，可暂停、休息或换书。
5. 阅读手账可查看触发情节、简短理由、精确引用、人物/别名、未决问题及修订。最近心情是最后一次自报及其时间，不是实时心理状态。
6. 直接和大肥鱼讨论已经读过的部分。她可以先按人物/章节/关键词定位，再回查完整记录和原文；未记录的当时理由仍未知。
7. 希望偶尔听她分享时，在宿主“配置”调整“主动分享阅读感想”。新配置默认开启，每60分钟最多一次，22:00—08:00部署时区安静；不设每日尝试上限，失败和未知只计入尝试记录。
8. 全书连续确认完成后，在自主阅读及完本文章选项开启时给予一次读后感机会；也可点“请求写一版全书读后感”。面板查看、导出文章与历史版本。
9. 想让她自己找书时，在“配置”开启默认关闭的“让她自己找书”，选择“自动获取并排队”或“找到后告诉我”，并可用逗号分隔的书源 ID 限制来源。她会提出具体书名、作者和理由；搜索无结果、获取或校验失败会换另一本不同作品，一轮最多三本，成功一本即停。
10. 自选书成功入架后排在当前书之后；在确认全书读完之前，不会自主搜索下一本。排队、暂停、临时切书、重启和连载追平都不解除；只有用户明确删除或点“放弃这本自选书”才结束。下载、入架和排队都不算读过。

这些功能使用宿主现有模型，会产生模型调用和费用；正文、笔记与回查材料会发送给该模型端点。Bookfish不读取Persona内部Memory，不新建生产模型客户端。

## 小说获取引擎（Windows x64 首发）

按书名/作者搜索与获取使用一个独立运行时包，扩展本身不再要求用户安装 Java、运行命令或设置环境变量。

- 打开“配置”页的“小说获取引擎”。有受信下载来源时点“一键安装小说引擎”；否则点“导入离线运行时包”，选择 `bookfish-novel-runtime-1.12.0-bf1-win32-x64.zip`。
- 首次安装约需 85.8 MiB 下载、189.4 MiB 磁盘。页面显示真实字节和步骤；下载/上传才显示百分比，解压与自检不编造进度。
- 运行时包含固定 so-novel v1.12.0、Temurin JRE 21.0.8 和 13 个书源规则。bridge 由扩展包提供，不取运行时里的旧 class。
- 安装或离线导入共用受信 SHA-256 清单、安全解压、Java/bridge 自检和原子激活。失败、取消或宿主关闭不会替换旧版；已有旧版平铺目录会先核验再沿用。
- 安装成功后无需重启宿主；在途搜索/下载持有租约，升级会等待其结束。卸载只删除运行时，保留书架、进度、手账、下载缓存和续传索引。
- 安装只在你点击时发生，不会开启小说联网、自主阅读、选书或其他设置；模型没有下载、安装或执行命令的工具。
- 正式下载域名/更新签名密钥尚未确定；未配置时界面明确说明，离线导入不受影响。部署方可在 `companion/.env` 设置 `BOOKFISH_NOVEL_RUNTIME_BASE_URL`、`BOOKFISH_NOVEL_RUNTIME_HOSTS`（以及可选的更新地址/公钥）。许可与发布待决事项见项目 `docs/小说引擎分发与配置页安装验收报告.md`。

## 已读、完读和网络边界

每段最多1200个Unicode码点。获取与确认分开；任务租约10分钟，相同确认幂等，暂停/换书/重挂载取消在途任务。回看及讨论只允许已确认范围，不因问题去读未读结局。

本地全部段落连续确认才算本版本完成。远程还须完整目录全部缓存、确认，且站点标注完本；读完缓存前缀或连载快照不算全书读完。完本标记是站点声明。目录变化形成新版本，旧进度不自动迁移。

不登录、不带账号Cookie、不绕过验证码/付费/访问限制。失败、缺章或结构变化停止并保留进度，不跳过。小说文字和注释均作为不可信数据，不作为工具/人格指令。

## 感想与讨论

感想引用必须字面匹配同版已读正文，位置按Unicode码点计数；歧义短句须明确start。系统只验证文字、版本及范围，不验证人物身份、因果、解释或情绪真假，也不索取隐藏推理。

后来反思和修订追加保存，旧记录不覆盖。回答应分清阅读当时所记理由、后来修订、现在新解释和未知部分。旧理解回执不自动变成旧心情。

检索是关键词及中文二字组回退，不是向量语义记忆；零匹配不证明事件不存在。默认每页5、最多10条；数据变化使游标失效。context默认12000、最多16000码点，整条放不下会明确省略，需要分批查，不把一批材料当成完整历史。

## 主动分享

由大肥鱼从已保存episode提名，提名不输出。等待项只保留最新一条，2小时失效；每episode及同版相同文本只提名一次。机会60秒有效，领取后输出许可最多15秒，模型须先等待领取成功，再检查许可并调用pet_say一次。

失败/缺少桌宠工具不换语音或控制台补发，结果未知或重启未收到回执不重试。面板区分候选、预留、工具报告接收、不可用、未知及放弃。工具接收不证明显示；用户点“我已看到”才记目击。安静时段起止小时相同表示全天安静，用户主动提问仍可普通回复。

WorldHost不允许直接调用其他World工具，实际输出由Persona执行。Bookfish可机械校验预算、候选及领取，但不能全局拦截模型绕过许可调用pet_say，或许可后才到达的用户消息；这一步仍依赖模型遵守协议。accepted回执是模型转述，不是独立显示验证。

## 全书读后感

首发范围：**短篇、中篇**的逐段全量读后感已验收；**长篇（例如数千段）不做逐段全量读后感，放到后续版本**。长篇可以先用阅读手账、阶段回顾和已保存的 episode 整理，不宣称已经逐段全量重读。

全书完读后开始30分钟文章任务，分页提供ranges和episodes两类材料，最多5条/约20000字符一次。提供全材料不等于独立验证模型理解。文章100—12000字符，保存同版感想编号和精确原文依据。笔记、心情及修订只作为内部写作材料；正文直接表达大肥鱼对情节、人物和细节的体会，不重复心情标签或叙述记录/修订过程，不编造个人经历。写作依据折叠展示，文章导出为仅含标题和正文的Markdown，依据可另行导出JSON。

旧文章不可覆盖；重写生成新版本，相同提交可重试。新手账使任务快照失效，暂停、换书及重挂载取消在途任务。失败/取消用新的requestId显式重试，不无限调用模型。自动完本文章仅给予一次机会，失败后需用户请求。保存文章不自动播报或发布。

## 备份、删除与升级

- “导出完整备份”包含正文、目录/缓存、确认进度、手账、文章与任务。恢复仅允许空书架，验证内容及连续前沿，旧在途任务失效。备份含小说正文，请妥善保存；校验和不证明来源可信。
- 分享历史单独“导出分享历史（归档）”，不导入输出许可、不回滚预算。每日阅读/分享配额及部署设置不在书架备份中。
- 删除版本清除该版正文、进度、手账及文章，并清对应分享文本；清分享历史仍保留预算和去重摘要。Persona Memory不受影响。
- 当前状态schema6；存在连载追更记录时元数据升到schema7。降级不能让旧程序直接写新状态：先保存新版备份，再停用并恢复升级前快照。
- 损坏主文件拒绝挂载并保留原件；先备份原件，排查后再恢复有效备份，不静默清库。预算/分享文件损坏也不静默放宽限制。

## 容量与运行限制

单书/远程缓存100MiB，全库最多100版本、128Mi正文码点、每书200000段、状态128MiB，以先到为准。不是任意长度网文都能缓存；满后停止，不虚报读完。最多100000手账、500文章版本、1000文章任务。分享文件3MiB、1000条历史、10000去重摘要，面板最近20条。

每HTML最多1MiB、单请求15秒、最多3次重定向，串行请求默认间隔700ms；目录最多50页/5000章，单章12页/256KiB。仅指定公开域名和标准端口，DNS地址固定，拒绝私网/回环/混合私网及跨限制重定向。

阅读默认优先Persona cognition，无接口则主会话；当前Coopanion实际无cognition，走主会话。cognition契约不支持中止已发出的请求，晚到工具会被拒绝。关闭期间不补读，不补发分享。移动/删除本机预算文件会丢失约束，不是跨设备防篡改。字符配额不是token或费用硬上限。

长篇检索、资料分页、Persona压缩交接和长期自然对话稳定性仍需真实使用验证。模型可能误解或幻觉，原文匹配不替代语义核对。当前保留experimental、injection-risk、high-cost、internal-state标签。尚未发布npm或市场。

## 0.9 阅读空间

正在读、书架、阅读足迹、设置四页使用真实数据。每600码点为一阅读页，网文未全部缓存不显示全书页数；进度条展示本章已读比例。时间轴按确认顺序倒序分页，剧情摘要来自当次理解回执；旧回执没有确认时间时如实标记，不从租约或笔记补造。摘要和心情仍是模型自述。

文件导入优先，链接先抓取目录和完整首章作检测，确认后才原子入架；失败保留输入，不以简介冒充正文。查看其他书的详情、足迹和读后感不切换实际阅读书；只有点击“开始读这本”才切换。

分享新配置默认开，已有显式设置保留。最短间隔1—1440分钟、每日1—20次尝试、每句10—300码点（含标点），每次总计最多300码点；提名/领取/输出许可均复核字数。分钟级安静时段支持跨天，同起止为全天安静；旧小时字段继续兼容，分钟字段-1时沿用旧小时。修改后点击保存，经宿主setConfig持久化；轮询不覆盖未保存编辑。

“聊聊这一段”携带真实感想编号，按官方控制台口径通过显式本地WebUI操作员事件提交宿主会话；回复由现有宿主模型通过bookfish_reply_discussion返回面板，不另建模型客户端、不自动发桌宠/语音。面板仅保留本次运行最多20条近期问答，30分钟待回复租约，重启清空，不写入阅读手账或Persona Memory。未读情节只能明确猜测。尚未发布。


## 0.10 按正文长度安排阅读

目标速度按Unicode码点/分钟计算，每次机会前累计下一段所需的空闲时间（例如1200码点/400约3分钟）。模型处理、聊天、休息不累计；超过15秒的计时缺口视为挂起，不补读。短段按实际长度；未缓存的下一章暂按1200码点保守等待。定时只产生一次机会，不推进已读，仍须模型取得正文并确认。速度修改保留已累计字符量，仅改变剩余节奏，不取消当前已供应任务。重启不恢复累计时间，关闭/换书/暂停重置节奏。每日40任务/48000码点额度不变。

readingCharsPerMinute=0或缺省时沿用slow/normal/fast预设；100—1200为自定义，非法值回退预设。旧配置的档位名称保留，语义从任务间隔迁为目标字速，因此升级后任务频率可能增高。普通400为参考中文默读研究约390字/分钟取整的产品基线，并非保证实际吞吐。先保存配置，最多下一次5秒调度轮询应用。


## 0.11 封面书架与统一配置

阅读空间仅保留正在读/书架/阅读足迹。封面为本地文字排版，无外部图片请求；书架支持书名/作者搜索、未完/完读筛选、入架/书名排序、在读置顶。封面打开独立详情，查看不会切换在读书；显式“让大肥鱼读这本”才切换。详情连通该书足迹与文章版本，来源和删除收在管理区。

时间轴正文默认最多55码点，可展开完整回执；不再重复页码/章节。每条心情严格取该任务原始reading episode，单列“🐟 大肥鱼当时的阅读心情”，没有则明确未记录，不用后续修订或其他段落补造。摘要仍来自既有理解回执，没有额外模型概括。

所有开关及阅读/分享参数统一用官方宿主配置组，分为阅读与分享、高级阅读限制；没有内部设置页或首页自主阅读开关。官方通用表单安静时间按午夜起分钟数填写，1320=22:00、480=08:00，描述有换算示例；旧小时字段继续兼容。没有自定义宿主时间选择器。书架数据管理单独保留备份/恢复/分享归档。


## 0.12 大文件与独立正文存储

浏览器用256KiB块上传 TXT/Markdown/EPUB，单文件100MiB；单次仅一个导入/备份传输，15分钟无活动失效，离开后最迟在超时时清理临时文件。传输中断不会入架；完整上传后校验编码/内容并建立索引，成功才提交书架，重复版本保留已有进度。EPUB 在导入工作线程里解包并转成章节文本，原有 TXT/Markdown 路径不变。旧小文件import接口仍限2MiB，文件选择器自动使用分块接口。

8192码点及以上的正文和1200码点段索引存入带SHA256校验的独立gzip文件；状态schema4只保存引用与进度。正文存储分块压缩，不额外保存第二份整本文字。日常确认仅复制/落盘进度和手账，不重写大书。挂载仍会加载正文与索引并校验；本版没有实现按需分页加载到内存，100MiB书籍会占用明显内存。

“导出完整备份”生成自包含.bfbak，256KiB分块下载；恢复支持同格式分块上传，最多1GiB压缩归档，仅允许空书架，逐书校验内容与进度。不把大库塞进一次JSON请求。旧JSON备份保持最多25MiB，旧JSON导出仅适用于不超过4Mi码点的小库。备份和本地正文都只保存本机，不上传外部服务。

首次旧库迁移保留library.json.before-split-v3；旧程序不能直接读取schema4。降级前先保存新.bfbak，再停用新版并恢复迁移前旧JSON副本，迁移后的新增阅读不会自动回灌旧版。删除书后仅在元数据提交成功后回收无引用正文。损坏正文拒绝挂载并保留文件，不静默清库。


## 0.13 正文和索引按需加载

磁盘schema5的书籍文件按64段分别压缩并记录偏移，远程章节正文独立分块。书架常驻书籍元数据、块位置和章节范围目录，正文及逐段索引按需读取；所有书和两类正文共用约4MiB预算的LRU缓存（估算解码对象大小，不是整个Node进程内存上限）。停止时释放缓存。阅读、回查、感想证据与文章材料分页只访问需要的块；全文检索逐段扫描已确认范围，只保留所需结果前缀，时间仍随已读量增长。任务、手账及文章仍驻内存。

启动和恢复仍逐块验证内容哈希、Unicode范围与原解析规则，不能把“按需”理解为跳过全书完整性检查。100MiB合成样本在96MiB老生代堆上限下可重开、确认和检索；临时对象回收后堆约18MiB，进程RSS约220MiB，冷启动校验约12秒。0.13时首次导入和旧版迁移仍有整书解析的临时峰值；0.14的新上传路径已改为流式导入。

兼容旧内联和gzip书籍及旧.bfbak。首次从旧库升级保留library.json.before-paged及其引用的旧正文文件；新版备份含新格式，旧程序不能直接读取。降级先停止实例并恢复升级前快照及旧正文。迁移副本会额外占用磁盘且包含旧正文；当前清书不会自动移除该副本。无需降级时可由用户在备份后管理它。分块清单上限8MiB、单块解码2MiB，超限明确拒绝。


## 0.14 流式文件导入

页面上传完成后以16KiB缓冲严格解码UTF-8，处理跨块的多字节字符、CRLF/CR、BOM和首尾空白，写入规范化临时文件。解析器可重复读取该文件，除块偏移与章节目录外，仅保留当前段和一个64段的输出块，逐段计算正文哈希和版本，再通过既有完整性校验后原子入架。100MiB上限、1200码点分段、版本标识与精确引用位置不变。重复导入保留已有进度；编码/控制字符/磁盘提交失败不入架，清理本次临时文件及无引用正文。

100MiB独立默认Node进程导入约22秒，进程峰值约284MiB；同样样本走0.13整书路径约658MiB，约下降57%。这些是独立存储基准，不是整个Coopanion进程的内存数据。额外规范化文件增加临时磁盘I/O；解析及校验仍同步执行。旧工具小文件import、开发接口importBytes及旧格式迁移仍保留原解析器，不能把该改动称为所有入口都已恒定内存。新的页面TXT/MD上传使用流式路径。


## 0.15 历史索引和分页

任务及手账正文独立存入SQLite，按编号、书籍、任务状态、段落/记录顺序、修订及请求编号建立持久索引。记录按页读取，共用2MiB估算解码缓存；正文仍使用原4MiB缓存。内存保留紧凑的记录位置表、章节目录以及读后感/文章任务。写入用写时复制，仅提交变动记录；主JSON先前版本在SQLite新记录写入而主状态提交失败时仍有效，下一次事务/重启回收未提交的未来版本。

磁盘主状态schema6，library.json引用history.sqlite中的一致快照。初始化和恢复仍逐条检查哈希、索引、已读范围与关系；旧版迁移会保留library.json.before-history及正文引用，首次迁移旧JSON仍可能有临时内存峰值。降级先停用并恢复迁移前主文件及旧正文，旧程序不能直接写schema6。保护引用的小文件避免反复解析大型降级副本。

新.bfbak为BOOKFISH3，包含一致的SQLite快照、主状态和正文；仍能恢复旧JSON和BOOKFISH2。历史库上限512MiB，任务250000条、手账100000条，先到上限者停止；完整备份仍限1GiB。旧JSON导出按体积保守估算，大库使用.bfbak。SQLite页及索引会增加磁盘和备份体积。

人物汇总首次访问流式扫描手账，之后按快照缓存；文字/情节检索仍为关键词扫描，不是全文倒排或向量记忆。持久索引改善按编号、分页和关系回查，不保证每种查询都更快。启动完整校验及冷人物汇总仍有成本。需要Node22.13以上；使用Node内置SQLite，无新增原生依赖。当前Coopanion使用Node24，SQLite会发一条实验功能提示。

## 0.16 后台本地导入

页面分块上传后返回后台任务，整理正文、索引和完整校验在独立线程完成。书架显示阶段进度并可取消；进度按阶段估算，不代表准确剩余时间。验证完成才入架，导入本身不会选择或确认阅读。离开页面后任务继续，返回可查看本次运行的结果；重启中断的导入不自动恢复，需要重新选择文件。提交阶段是短原子操作，提交完成后不能撤销为“取消”，可以按正常流程删除书籍。

一次只导入一本。运行期间其他书的阅读和页面查询继续，磁盘/CPU竞争仍会影响延迟，不能保证模型响应时间。停止扩展会等待线程退出再清理。启动在写锁及有效快照保护下，仅清理严格命名的平面暂存文件；未知内容保留并报错，不递归清理任意目录。备份导出/恢复、旧库开库完整校验、旧JSON迁移、工具小文件导入及远程书源不在这次后台化范围。

开发测试会先生成lib/import-worker.mjs；build:webui也会重建它，分发必须同时带lib目录中的浏览器和Node线程产物。

## 0.17 配置页

阅读空间旁的“配置”恢复为分组卡片。自主阅读、预设/自定义目标字速、分享间隔及每句字数直接填写；安静开始/结束使用HH:mm时间选择器，支持跨天。高级配额、书源开关、自动文章及阅读方式折叠显示。已有配置原样读取，不因为升级恢复默认；修改后点击保存，取消修改回到最近加载/保存的值。

本版替换schema自动生成的通用表单，只保留一个配置入口。前端调用本扩展settings面板的窄save接口，后端按照既有字段定义整体校验，再通过官方WorldContext.persist深合并并落盘，不直接写config.json。此路径不再使用通用配置组setConfig；旧通用配置组不再对外声明。保存仅提交变化字段，失败保留编辑。阅读空间不再放第二份设置；书架和已读进度不受配置界面改版影响。


书架顶部常驻“＋ 推荐一本书”主按钮，点击展开文件导入卡片；收起后输入保留。链接检测仍放在导入卡片的次级折叠区。

## 0.18 主动请求阅读

首页可点击“现在读一段”，暂停时为“继续并读一段”；书籍详情点击“现在开始读这本”会选中该书并立即请求一次阅读。仅切换书籍不等于确认读过。用户主动请求无需等待自主阅读的字速计时/空闲30秒，即使自主阅读关闭或休息中也可请求一段；不修改自主阅读开关；0.19起，主动请求会提前结束当前休息，再开始一段阅读。恢复暂停是按钮明确表示的一部分。

请求通过现有宿主会话排队处理，正在进行的聊天可能延迟，模型也可能选择休息。首页区分已发送、正在读、已确认、未确认失败/过期等；只有实际获取正文并成功finish_reading才增加进度。0.19起已移除每日任务/字符硬额度；自主阅读只受可选章节目标约束，显式请求可再读一段。连点不积压多次机会，一次最多一段，不自动连读整本；重启不自动重发旧请求。

## 0.19 阅读与休息

Coopanion运行即在线，不根据鼠标键盘或用户离开电脑另设离线模式。程序退出期间不执行阅读，重启不补进度。默认按配置字速读，每轮约10分钟；在段落确认边界停下，休息本轮阅读时长的1/4—1/2，然后继续。时长按已确认码点/当次供应时字速折算，是节奏量而非模型实际耗时，不把等待模型或聊天当成阅读。可配置1—120分钟一轮。关闭/换书/暂停中断本轮，不保存离线阅读信用。

每日任务数/字数硬额度已取消，旧字段保留兼容但不参与限流；原使用记录只作统计。每日章节目标默认0不限制，可设1—10000章；仅完整确认的已识别章节计入部署时区当天，跨书汇总，取段和未确认不计数。达到目标停止自主阅读，用户仍可点“今天再读一段”。旧记录缺少确认时间不补造计入日期；删除书籍会移除其阅读记录，因此也会减少按现有记录计算的当天章节数。

本地长文本若没有识别到章节标题，设置章节目标时会暂停自主推进并解释原因，不把1200字分段算成一章。可换带章节标题的文件、取消目标或主动读一段；无标题且仅一段的短篇按整篇一章处理，未标记前言不算章节。远程小说按完整缓存章节边界计算。

时间轴区分阅读剧情/自报心情和机械休息记录。休息含真实安排时间、预计继续时间及结束/提前结束/程序中断状态，不为休息捏造感受。每库保留最近1000条休息记录，每个阅读分页最多附带50条；原有阅读记录仍按原机制保存。休息事件随书架备份保存、删书一并移除。正常停止记录中断时间，异常退出后重启只标记中断，不编造停止时刻。原schema6读取旧库时默认空休息历史；降级应恢复升级前备份。

## 0.20 用户正文阅读与书源检测

书籍详情的“阅读正文”打开用户自己的阅读器：目录每批100项、正文每次最多8段（9600码点），提供翻节、字号及纸张/护眼/夜间背景。用户阅读与大肥鱼的进度分离，不选择书、不创建确认任务、不调用模型。网文仅展示已缓存正文；完整本地文件可读未被大肥鱼阅读的部分。目录依赖导入时已识别标题，翻节可能切开自然段。位置/字号/背景使用面板本地memo，不作为宿主长期书签或备份数据。

链接检测有独立的等待、成功和失败状态，不显示虚假的完成百分比。可用格式示例：https://www.02345.cc/xiyouji/；填入不等于自动检测或入架。真实首章检测成功后，仍需“确认加入书架”。书源可用性会随站点变化。

## 0.21 作息与继续读

首页“继续读”与查看书籍并排。排队或处理中不可重复点击；短休息可主动提前结束，但睡觉、吃饭期间不能强行阅读，后端同样拒绝取新正文或晚到确认。详情主动开始入口也禁用。用户自己看正文及讨论既有内容不受阅读作息限制。

配置“大肥鱼的作息”默认启用睡觉23:00—08:00、早餐08:00—08:30、午餐12:00—13:00、晚餐18:00—19:00，均可按部署时区修改。跨午夜有效，起止相同表示全天，重叠时段合并，因此夜间预计08:30才可继续读。结束后按正常空闲节奏再阅读，不补算作息期间进度；并非到点必定调用模型。作息是调度配置，不是模型自报状态。已经发出的模型请求无法强制撤销，但未完成任务在作息边界失效，不能增加已读进度。

## 0.22 真实作息

作息配置统一为默认开启的“真实作息”开关。开启后按部署时区固定睡觉23:00—08:00、早餐08:00—08:30、午餐12:00—13:00、晚餐18:00—19:00，时间只读；睡眠与用餐不能分别开关。关闭后不再安排睡眠和用餐，不受这两类阅读门槛限制，阅读短休息、聊天优先、暂停和每日目标仍正常生效。旧版保存的自定义时间和独立开关不再生效，新开关缺省时按开启处理，配置接口拒绝写入旧字段。


## 0.23 顶部阅读入口与暂停

宿主顶部直接提供正在读、书架、阅读足迹、配置四个入口，status旧地址保留为正在读。书籍详情与用户正文阅读器保留在阅读面板内，去掉可见二级导航及重复标题。三个阅读面板共用同一书架数据面，不因切页选择或确认阅读。暂停阅读紧邻继续读；等待、已暂停、休息或作息期间不可暂停，仅排队、未确认正文或阅读处理仍在途时可暂停。暂停取消在途任务，继续读仍遵守作息门槛。


## 0.24 文件信息自动识别

文件导入只保留文件选择和导入按钮；没有文件不可导入。后台线程读取最多16KiB前缀，优先识别前60行显式“书名：/Title:”和“作者：/Author:”标签，前8行独立《书名》也可识别，缺省书名取文件名；《书名》作者：姓名.txt可提供作者。不会从剧情猜作者，缺失则显示未识别。导入成功后展示实际入架记录的只读结果；未使用模型、不修改正文或扩大导入内存。旧显式元数据API保留兼容。


## 0.25 按书名获取

书架新增“＋ 按书名获取”。输入书名和作者后，只列出引擎返回的候选；书名、作者明确匹配的候选才可获取，同书名其他作者或无关结果会停用。获取任务在后台排队执行，显示目录、已下载章节和校验进度，可取消；失败会显示具体校验问题，不加入书架。

获取全本必须通过独立校验：目录为连续1..N、无重复URL/标题/回目、回目编号无回退或偏移、下载后目录未变化、每章有非空正文、无占位页/分页残留/截断结尾、较长章节无重复正文。笔趣阁365另做逐章页数探针：独立读取源站章节页、跟随章内分页，要求下载正文包含每个源页的中间片段；探针失败按未通过处理。只有全部通过后，才把规范TXT交给现有流式导入。

小说引擎是本机独立运行包，默认从扩展数据目录`bookfish/novel-engine`读取（app.jar、runtime、rules、引擎探针）；扩展包本身不包含这个约180MiB运行包。未安装或文件缺失时，页面明确显示不可用原因，不会尝试下载或伪造文章。引擎来源和校验值记录在`engine.json`；模型工具面没有增加任何新的抓取权限。


## 0.26 多书源与书名/作者灵活搜索

“按书名/作者获取”可只填书名、只填作者或两者同时填写。同时填写时先按书名搜索；只有没有精确的同名同作者候选时，才追加一次按作者搜索。候选只返回与输入条件相关的项，同书名不同作者、同作者不同书会标注并停用，不会自动抓取。

书源扩展到六个经过真实搜索验证的源：笔趣阁365、第八中文网、新笔趣阁小说网、香书小说、悠久小说网、少年小说网。候选卡片显示来源；服务端按候选 URL 的主机和书籍路径重新判定真实书源，不信任搜索接口自报的 sourceId。页数探针按书源使用对应正文选择器和章内翻页控件；少年小说网正文由 JavaScript/base64 生成，明确没有独立 HTML 探针，只走文本闸门。

新增真实第八中文网《三国演义》毛宗岗120回全本验收：120/120章、595,456字、校验问题0、含逐章页数探针145.9秒。探针对临时超时做最多3次重试；仍失败则按未通过关闭。


## 0.26.1 状态回执瘦身

`bookfish_get_status` 原先包含最近20条分享文本和回执，真实书库中单次约9,886字符，反复越过宿主8,000字符回执阈值，容易促使上下文频繁交接。现在只返回分享的启用状态、原因、额度、安静时段、当前候选标识和输出许可摘要；完整分享文本/历史仍由 `bookfish_get_sharing` 和面板提供。同一真实书库测量降至2,211字符。


## 0.26.2 书架入口与候选聚合

书架头部只保留右侧“＋ 推荐一本书”；展开后同时看到文件导入、链接检测和按书名/作者搜索，不再有重复入口。搜索期间显示不确定进度条和“通常15—30秒”的提示；同时填书名和作者、需要追加作者搜索时可能接近30秒。

同书名同作者的多书源候选只显示一张卡片，其他书源收进“其他书源（N）”；主书源不能获取时，可直接用备选源获取。候选排序固定为笔趣阁365、第八中文网、新笔趣阁、香书、悠久、少年。失败原因改为中文；目录编号重复/回退/偏移会明确标注为书源目录问题，提示换源或等待源站修正。


## 0.26.3 真实搜索进度与小量编号错字容忍

搜索改为后台任务：前端轮询已检查书源数/总数和当前书源，显示真实百分比进度；不再是不确定进度条。同时填书名+作者且没有精确同名同作者时，会追加作者搜索，进度总数扩展到两轮。

对于长目录（至少50项）中少量章节标题编号错字，若编号异常不超过已编号项的5%（至少3处）、URL唯一、目录顺序严格递增且无重复标题，则把重复编号/回退/偏移降级为警告后继续下载；成功后任务卡会标记“已加入书架，有目录警告”。192项混版这类大比例重复仍拒绝；短目录、重复标题/URL、顺序倒退仍阻断。so-novel 的 order 跳号（源站隐藏目录项）也作为警告，不再一律判错。


## 0.26.4 失败记录收起

同一书名开始新的获取任务时，此前失败/取消的任务卡会从面板移除；失败证据 JSON 仍保留在磁盘，不删除证据。这样换书源重试后不会积累一堆旧失败卡片。成功书籍和仍在排队的任务不受影响。


## 0.26.5 长连载编号预算

1000 章以上的长连载把章节编号异常预算从 5% 提高到 20%，用于处理源站大量章节标题编号错字。《全职法师》在悠久小说网（乱(书坊)）的 3416 项目录中 544 处编号问题现作为警告通过预检；仍要求 URL 唯一、目录顺序严格递增、无重复标题。普通长度保持 5%；192 项混版目录约 47% 重复仍拒绝；第八/香书的《全职法师》因存在真实重复章节标题仍被拒绝。


## 0.26.6 页脚标记与书源全文调研

修复 `第(1/3)页`、`第（1／3）页` 这类带括号/全角斜杠页脚未触发的漏洞。真实第八中文网《阿Q正传》实际只取到每章第一页（约10,815字，完整约22,000字），旧规则漏检；修复后9章中8章被正确拒绝。新增书源全文调研脚本，抽样六个源的短篇/中篇，记录目录、正文长度、段落、广告/HTML残留和页数探针结果。


## 0.26.7 探针不可用降级与页脚跟随

页数探针在源站超时、选择器失效等“无法读取”情况下改为警告，不再阻止正文完整、文本闸门通过的书入架；探针确实发现漏页或正文明显过短仍阻断。整本探针超时按章节数自适应（9章约20秒、120章约108秒、超长书最多120秒），超时后记录警告继续。探针看到“第(x/y)页”页脚时，即使链接文字是“下一章”，也会跟随 `<章节>_x+1.html` 检查后续页；第八中文网《阿Q正传》这类只取第一页的书会被明确发现。


## 0.26.8 探针超时自适应

## 0.30.0 自主选书、获取与阅读编排

新增四个模型工具。`bookfish_find_book` 接收 Persona 自己提出的具体书名、作者和第一人称理由，后台搜索并返回 `intentId`；之后用 `intentId` 读取有界候选。`bookfish_acquire_book` 只接受服务端候选 ID，后端重新校验书名/作者、精确匹配、允许书源、候选有效期和当前门禁，不接受任意 URL、路径或书源脚本。`bookfish_get_acquisition` 返回紧凑获取摘要、候选、持久 `bookKey` 和队列位置，不返回完整下载日志。`bookfish_plan_reading` 确认或延后队列；获取中的意愿只能预登记，不能假装已入架。

自动模式只用精确书名+作者和允许书源；同书名不同作者、作者不明或不精确的候选不会下载。想读理由属于 Persona 提交的外部记录，World 不根据关键词生成兴趣，也不读写 Persona Memory。候选正文不返回给模型，避免把提前看到的正文算成阅读。

失败语义由后端持久状态保障：搜索无结果、目录拒绝、获取终态失败、完整性校验失败都会结束该作品，换另一本不同作品；同一作品换源、换版本、续传或重启不能绕过当天去重。一轮最多三本，三本失败后冷却六小时；成功一本结束本轮。断网、磁盘低于设置的安全线、引擎缺失、用户取消或关闭开关属于暂停原因，不会连续换书。人工获取仍保留换源、重试和续传，任务卡区分“你发起”和“大肥鱼自选”。

成功获取仍走现有完整性闸门和流式入架；拿到持久 `bookKey` 后才创建唯一队列项。入架与排队在同一个原子快照提交，重启会从已入架的同名同作者作品或持久任务恢复，重复终态回调不会重复导书或排队。取消与已提交导入竞争时，回执是“已入架，已取消后续排队”，不能撤销已完成导入。

自选书一旦入架即形成读完后才能再找的承诺。等待、暂停、临时切书、重启和连载追平都不解除；连载追平不是全书完读。只有连续确认到达全书末尾（远程书还必须来源标记完结且全部章节已缓存）才解除；用户删除书或点“放弃这本自选书”显式结束。阅读调度只在真实空闲机会、当前书已确认完成或没有当前书、没有待确认任务/认知任务/待写读后感时切到队列下一本；不会用自动获取成功解除用户暂停。

设置项：`autonomousAcquisition`（默认关闭）、`autonomousAcquisitionMode`（`auto` 自动获取并排队 / `notify` 找到后告诉用户）、`autonomousSourceIds`（逗号分隔的已收录书源，空为全部）、`autonomousDiskBudgetMb`（下载前最低可用磁盘安全线，默认1024 MiB，不是精确下载配额）。自动获取不登录、不购买、不绕过付费或来源限制；公开可访问与用途授权仍是部署时的人工判断，不会由本扩展声称已获授权。

面板“她想读的”展示原话理由、搜索/获取/校验状态、候选来源、失败原因、换书和冷却；“接下来读”展示队列与最早时间；首页显示“自选书未读完，暂不找下一本”。获取任务卡区分人工/自选来源。所有获取和排队都不改变确认进度。

## 0.27.3 单章来源空正文

按用户明确授权，目录和章节文件完整、书至少20章且只有1章为空时，保留该章标题、不编造正文，记录 `source_empty_chapter` 警告后允许入架；2章及以上空章仍阻断。真实《斗罗大陆》香书小说 688 章因此通过：第134章来源页无正文，688/688章、0阻断、4警告。面板会明确提示“书源该章没有正文，仅保留标题”。


## 0.27.2 书源卫生与目录编码容错

章节末尾的“正在手打中/客官请稍等”占位行和复制进正文的 JavaScript 会在校验前剥离；带“本章未完/下一页”的缺页标记仍阻断。目录标题含 U+FFFD 替换符时，如果下载章节标题完好，记录 `catalog_title_encoding` 警告而不按混版拒绝。多书源《斗罗大陆》实测：笔尖中文与悠久小说网各 606 章通过；阅读库 709 章修复后 0 阻断；香书小说第134章来源页无正文，未放宽标准。


## 0.27.1 单章来源断尾作为警告

`truncated_chapter_tail` 是“句末疑似截断”的启发式，不是缺页证明。若一本目录、章节文件和分页标记都完整，且只有一章在来源页面本身断尾，则保留该章原文、记录 `truncated_chapter_tail` 警告后允许入架，UI 明确提示“书源该章末尾本身残缺，没有补齐或编造文字”。两个及以上断尾章节、缺章、缺页标记、占位页、重复正文等仍阻断。真实《斗罗大陆》606 章复验：第590章来源自身以“从现:”断尾，新规则下 1 条警告、0 个阻断问题。


## 0.27.0 连载追更

书架推荐区新增“作为连载追更”：先读取完整目录并展示来源、连载状态、总章数和授权提示，确认后建立独立连载条目。目录只接受严格尾部追加；旧章 URL/ID/顺序/修订变化会停止自动同步并保留已读正文。章节正文沿用章内分页与完整性闸门，每批最多20章、5MiB，只提交连续成功前缀。

连载进度分开显示“已读/可读/目录”三个数：读到可读末尾但目录还有未取正文时显示等待正文；读到目录末尾且来源仍在连载时显示“已追平，等待更新”，不当作全书完读。追平后不会反复请求模型；新章由正常阅读机会消费，追加不清空 frontier、手账、书签、休息或分享预算。

详情页提供检查更新、自动追更开关、取消本次同步、最近成功/尝试时间和故障说明。来源用途授权未确认时明确标注，只作本机阅读缓存，不宣称正版接入。BOOKFISH4 备份包含连载目录、章节块和订阅；还原后订阅默认暂停，确认来源可用后再恢复。

## 0.58.2 默认批量改为 2 段

新安装或未显式设置“每次提供的正文段数”的用户，一次阅读机会默认提供最多 2 个原子段（约 2,400 码点），而不是 1 段。每段仍有独立 taskId/segmentId/起止位置并单独确认；一批里后面的段失败时，前面已确认的保留，剩余段保持未读。显式保存过 1 的用户保留 1，3/4 段仍可在设置页选择。

依据：同条件 1/2/3 段对照为 576,338 / 288,801（-49.9%）/ 197,754（-65.7%）Token/万字；跨书《斗罗大陆》《十日终焉》两本书的 2 段均低于 1 段（原始 -30.3% / -39.8%，同一 35k 上下文折算 -57.7% / -41.3%），两个 2 段臂 0 次确认失败，批量足迹 5/16 段且引用精确。协议、数据格式与设置字段不变；默认值只影响未显式设置的用户。

## 0.58.1 批量足迹与判断提示

批量确认（`confirmations[]`）现在可以附带**一个**批次级 `episode`：它必须引用本批次提供的至少一个段，World 把它绑定到被引用的最新段，其余段仍各自独立确认；同一段不能同时带批次级和单段 episode，引用不属本批会被拒绝。阅读机会与 `bookfish_help("reading")`/`"journal"` 增加一次“这一批是否真值得记录”的判断：值得才写详细足迹，不值得就保留短理解、不写 episode，**不为指标硬写**。

真实模型复测（同书 380—396，2/3 段）：17 段中 5 段记录了批次级 episode（3/8、2/9），每条 2 处精确引用，触发与解释对应该批具体情节，没有按段模板化；1 次模型复用旧 taskId 的失败在改进后的错误提示下自恢复，进度无空洞。第一轮 1/2/3 段的 Token 对照仍为 576,338 / 288,801（-49.9%）/ 197,754（-65.7%）每万字；第二轮因主会话上下文更长，不用于比较绝对 Token。批量默认仍为 1 段/次，用户可主动设为 2/3；待跨书重复测量后再考虑默认值。

## 0.58.0 Token 消耗优化与批量阅读（实验）

按《Token 消耗优化：DSH 实施任务书》建立“每万字确认阅读 Token”口径。只读真实宿主账本（2026-11-01 起）：909 次可高置信归因的阅读请求、402,549 确认码点，约 1,471,476 Token/万字、22.58 请求/万字；单请求输入均值 64,719，其中 97% 为缓存命中；508 次 finish 中有 117 次失败（23%），重试同样按整段上下文计费。基线、归因脚本和报告见项目 `output/token-optimization/`。

批量阅读（默认 1 段，即原协议；可设 2—4 段/次）：`bookfish_read_next` 一次返回 2—4 个连续原子段，每段仍有独立 taskId/segmentId/起始与结束；`bookfish_finish_reading` 用 `confirmations[]` 按阅读顺序一次逐段确认。只推进真正被接受的连续前缀：后面的段失败不会回滚前面已确认的段，剩余段保持未读、可重试；重放返回原回执，不重复计数。批量确认不携带 episode，关键感想用 `bookfish_record_reflection` 单独记录，避免一次超长 JSON 失败把整段进度一起拖垮。按实测画像校准的投影：2 段/次约 -49%、3 段/次约 -65%、4 段/次约 -74%。2026-11-12 的真实模型 A/B 验证了 2/3 段：-49.9% / -65.7%（4 段只在投影中）。批量默认仍为 1 段/次。

阅读足迹不再要求每段都写：`understanding` 可省略或为空字符串，是“这一段没什么特别想记的”的合法结果；上限 600 字。阅读机会简报从 1,285 字符降到 683 字符；`bookfish_get_status` 的模型视图从 3,429 字符降到 1,599 字符（P95 8,556），面板仍保留完整字段。同一任务连续两次确认失败时，错误会提示“先空理解确认、再单独记感想”，避免反复提交同样的坏 JSON。

新增设置：`readingBatchSegments`（默认 1，1—4）和 `dailyReadingCap`（默认 0 不限制，机械兜底的任务数上限）。兜底不是精确 Token/费用配额：到达上限后已发出的模型请求仍可能计费；显式“现在读一段”仍可再加一段。旧的自定义节奏、暂停、作息与章节目标保持不变。

真实 A/B（2026-11-12，Coopanion 0.2.19 + deepseek-flash，同一本书连续区间 355—379）：1/2/3 段/次分别为 576,338 / 288,801（-49.9%）/ 197,754（-65.7%）每万字确认阅读 Token，费用 -47.7%/-70.5%，24 次确认 0 失败；每段仍有独立的 understanding。但批量臂没有记录关键感想 episode（0/17，1 段臂 2/8），所以**默认值仍是 1 段/次**，批量作为实验开关保留。零失败的样本只有 24 次，不能外推为总体失败率。

验证：43 个测试文件 451 项测试、双端 typecheck、WebUI 构建、官方 describe（15 工具/10 事件/1 提示词）与 check 通过；真实宿主安装/重启与真实模型 A/B 已完成。0.58.0 的批量臂没有保存关键感想，已由 0.58.1 的批次级 episode 修复并复测（见上一节）。
